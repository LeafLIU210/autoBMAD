### Phase 2: Reduce Drift

Goal: one state contract and one tool-security contract.

Actions:

## 架构决策：状态所有权 (State Ownership)

**决策日期：** 2026-05-02
**决策编号：** ADR-STATE-001
**状态：** Accepted
**关联 ISSUE：** ISSUE-1, ISSUE-4, ISSUE-5, ISSUE-9

### 背景

`pipelines` 表同时维护顶层列 `status` / `current_node` 与 `state_json`。审计发现 2 条真实 mismatch 记录；一致性测试在并发执行时超时；`get_pipeline` 读路径使用 `state.get("status", row["status"])` 的双源 fallback；`list_pipelines` 与 stale-running 扫描仅依赖顶层列；多条旁路写（历史 `UPDATE pipelines SET status=...`）未收敛到单一入口。

### 决策

采纳 **方案 A：`state_json` 为唯一逻辑权威（SSOT），顶层 `status` / `current_node` 为物化投影列（materialized projection）**。

### 契约

| 维度 | 规则 |
|---|---|
| 逻辑权威 | `state_json` 反序列化后的 `PipelineState` |
| 物理索引 | 顶层列 `status` / `current_node`（仅供 WHERE/ORDER BY/索引使用） |
| 写入入口 | **唯一**：`StateManager.update_pipeline_state`；一条 `UPDATE`、一个事务、同步两处 |
| 读——详情 | `get_pipeline` 以 `state_json` 为准；`state_json` 为空视为数据损坏 |
| 读——列表 | `list_pipelines` 读顶层列（只读不写） |
| 健康检查 | 启动/定期扫描 `status != json_extract(state_json,'$.status')`，发现即以 `state_json` 为准回填并告警 |

### 代码层改动清单

1. `StateManager.update_pipeline_state`：
   - 取消先 `_pipeline_exists` 再 `UPDATE` 的嵌套连接模式，改为单次 `UPDATE ... WHERE pipeline_id=?` + `rowcount` 判 0 报错；连带缓解 ISSUE-1 的挂起风险。
   - `top_status = current_state["status"]`（不再 `.get(..., None)`），缺失即抛 `StorageError`。
2. `StateManager.get_pipeline`：
   - `"status": state.get("status", row["status"])` → `"status": state["status"]`；`current_node` 同理。
3. `HybridOrchestrator.start_pipeline`（ISSUE-4 连带修复）：
   - 若调用方传入 `pipeline_id`，直接 `create_pipeline(..., pipeline_id=pipeline_id)`，**不再**先生成再 swap。
4. `IndependentAgent._on_session_created`（ISSUE-9 连带修复）：
   - 去掉 fire-and-forget `loop.create_task`，改为在节点执行边界显式 `await` 后返回；否则写入契约被绕过。
5. 一次性数据清理脚本：
   - 对 `pipeline-1777391639065-c7afe16e`、`pipeline-1777380083297-cc65c03f` 以 `state_json` 为准回填顶层列。

### 测试契约

- **`test_state_projection_consistency`**：对每个 `update_pipeline_state` 调用后执行 `SELECT status, current_node, json_extract(state_json,'$.status'), json_extract(state_json,'$.current_node') FROM pipelines WHERE pipeline_id=?`，断言两两相等。
- **`test_explicit_pipeline_id`**：`start_pipeline(pipeline_id="p-custom")` 必须在 5 秒内完成，且 DB 中主键即为 `"p-custom"`。
- **`test_get_pipeline_requires_state_json`**：`state_json` 为 NULL 时 `get_pipeline` 必须抛错，而非静默 fallback。
- **`test_health_check_detects_mismatch`**：人工制造 mismatch 后，健康检查必须捕获并按 `state_json` 修复。

### 迁移路径（低风险、可回退）

1. Week 1：合并写入口收敛 + 读契约收紧 + 新增一致性测试（向后兼容，旧数据仍可读）。
2. Week 1 末：运行一次性清理脚本修复 2 条历史 mismatch。
3. Week 2：启用启动期健康检查与结构化告警。
4. Week 3+（可选）：评估切换到 `GENERATED ... STORED` 列，彻底移除应用层同步代码。

### 权衡与拒绝项

- **拒绝方案 B（顶层列为权威）**：需要把 deliverables/questions/evaluations/session_ids 等复杂结构全部拆列；迁移面过大，与 LangGraph checkpoint 的 TypedDict 演化方向相反。
- **拒绝方案 C（删除顶层列，只保留 `state_json`）**：`list_pipelines`、stale-running 扫描、CLI 列表命令失去 B-tree 索引，随数据量线性劣化；SQLite 表达式索引维护复杂，ROI 不足。

### 连带收益

- ISSUE-1：收敛嵌套连接后，挂起的 Heisenbug 概率大幅下降。
- ISSUE-4：写入入口统一后，显式 pipeline_id 不再存在创建-替换空档。
- ISSUE-9：写入契约明确后，fire-and-forget 自然被替换为 awaited 写入。
