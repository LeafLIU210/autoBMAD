## Acceptance Criteria
- [x] WAL mode enabled for concurrent reads - The database must use Write-Ahead Logging (WAL) journal mode to allow concurrent read operations without blocking
- [x] Foreign keys enforced - SQLite foreign key constraints must be enabled to maintain referential integrity between related tables
- [x] Busy timeout configured (5000ms) - The database must be configured to wait up to 5000ms when encountering lock contention before raising an error
- [x] Tables created on first run - The schema initialization must automatically create all required tables when the database is first accessed
- [x] Connection pooling for efficiency - The implementation must support connection reuse to avoid the overhead of creating new connections for each operation

## Dev Notes
- **Database Location**: Store the database file in the project root or configurable path via environment variable `DB_PATH`
- **Schema Design**: Use TEXT columns with JSON serialization for complex data (deliverable, questions, evaluation, answers, chained_context) to maintain flexibility
- **Index Strategy**: Create indexes on node_id, context_hash, and status columns for efficient query performance
- **Concurrency**: WAL mode allows concurrent reads but requires careful write transaction management
- **Error Handling**: Wrap database operations in try/except blocks to handle locked database scenarios gracefully
- **Initialization**: Use `IF NOT EXISTS` clause in CREATE TABLE statements to support idempotent initialization
- **Type Safety**: Use Pydantic models for serialization/deserialization of JSON fields
