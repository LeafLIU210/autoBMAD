# Story 31.1: Extend NodeToolPermissions with Skills Config

## Status

**Status**: Ready for Done

**Last Updated**: 2026-04-07 08:36:51

## Story
**As a** system architect,
**I want** to extend the NodeToolPermissions dataclass to support Skills configuration,
**so that** each node can have per-node skill whitelists and SDK native skills can be enabled/disabled via configuration.

## Acceptance Criteria
- [x] `NodeSkillsConfig` dataclass exists with all required fields: `sdk_native` (bool), `whitelist` (list[str]), `quick_reference_enabled` (bool), `quick_reference_include_descriptions` (bool)
- [x] `NodeToolPermissions.skills` field is populated from `node.yaml` `tools.skills` section
- [x] Backward compatible (nodes without `skills` config still work - use sensible defaults)
- [x] Unit tests pass for config loading with and without skills configuration

  - [x] Add docstring explaining each field's purpose
- [x] Task 2: Extend `NodeToolPermissions` dataclass (AC: #2)
