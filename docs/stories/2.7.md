## Dev Notes
- The Evaluator Agent must ONLY receive subject_context and deliverable - never private_reasoning
- Use Kimi K2.5 "thinking" mode for analytical evaluation (temperature: 0.5, max_tokens: 8000)
- Universal criteria weights: completeness (0.30), clarity (0.20), consistency (0.20), actionability (0.20), evidence_quality (0.10)
- Per-node weight overrides should be loaded from evaluator.yaml (e.g., analyst: evidence_quality=0.40)
- Response parsing must handle both direct JSON and JSON in code blocks
- All scores must be clamped to 0.0-1.0 range
- Include comprehensive error handling for malformed LLM responses
- Follow Ralph's principles: DRY (use shared parsing utilities), KISS (simple weighted calculation), YAGNI (no extra metrics)
