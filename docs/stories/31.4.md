### Configuration Structure
The `tools.skills` section must be added at the root level of each node.yaml file, alongside existing sections like `node_id`, `name`, `agent`, `task`, etc. The structure follows this pattern:

```yaml
tools:
  skills:
    sdk_native: true
    whitelist:
      - bmad-skill-name-1
      - bmad-skill-name-2
      - bmad-advanced-elicitation  # All nodes get this
    quick_reference_enabled: true
    quick_reference_include_descriptions: true
```

### Technical Considerations
1. **Backward Compatibility**: The `tools.skills` section is new. Existing nodes without this section should continue to work (handled by Story 31.1 loader changes).
2. **YAML Indentation**: Use 2-space indentation consistently. The `tools` key is at root level, `skills` is nested under `tools`.
3. **Skill Names**: Use exact skill identifiers as they appear in `.claude/skills/` directory (e.g., `bmad-product-brief` corresponds to `.claude/skills/bmad-product-brief/SKILL.md`).
4. **Order Preservation**: Add the `tools` section near the end of the file, before `evaluator` section if present, to maintain logical grouping.
