## Status

**Status**: Ready for Done

## Story
**As a** developer,
**I want to** implement path traversal protection in the ContextResolver
**So that** malicious users cannot access sensitive files outside the project directory through crafted @ references.

## Acceptance Criteria
- [x] `../` path sequences in references are rejected and blocked
- [x] Absolute paths that resolve outside the project_root are rejected
- [x] When a path is blocked, the ReferencedDocument contains a non-null `error` field with a descriptive message
- [x] Security events (blocked access attempts) are logged with appropriate log level (WARNING or higher)
- [x] Symlinks are resolved before the safety check to prevent bypass attempts
- [x] The error message clearly indicates that the path must be within the project directory

## Tasks / Subtasks
- [x] Task 1: Implement `_is_safe_path(self, resolved: Path) -> bool` method in ContextResolver
  - Use `Path.resolve()` to resolve symlinks first
  - Use `Path.relative_to(project_root)` to check if path is within bounds
  - Return True if safe, False otherwise
- [x] Task 2: Integrate `_is_safe_path` check in `_resolve_single_reference` method
  - Call after resolving the path but before checking file existence
  - Return early with error if path is unsafe
- [x] Task 3: Add security logging for blocked access attempts
  - Log at WARNING level: "Path traversal denied: {ref_path} -> {resolved_path}"
  - Include context_file_path in log if available
- [x] Task 4: Create comprehensive test cases for path traversal scenarios

## Dev Notes
- **Security Consideration**: Path traversal attacks use `../` sequences to escape the project directory. Always resolve paths before checking safety.
- **Symlink Handling**: Use `Path.resolve()` which resolves symlinks to their real path. This prevents attackers from using symlinks to bypass the check.
- **Error Handling**: The error message should be user-friendly but not reveal internal paths. Use "must be within project directory" rather than exposing project_root.
- **Implementation Location**: The safety check belongs in `utils/context_resolver.py` in the `ContextResolver` class.
- **Performance**: Path resolution is relatively fast; no caching needed for this check.
