## Dev Notes
- All exceptions should accept optional `context: dict` parameter to store contextual information (e.g., node_id, run_id, file paths, etc.)
- Exception messages should be human-readable and actionable
- Consider using `__init__` override to ensure context is stored as instance attribute
- The base `DocuSwarmError` should have a `context` property that returns stored context or empty dict
- All exception classes should inherit from `DocuSwarmError` for proper catch hierarchy
- Consider adding `to_dict()` method for serialization when storing exceptions in logs/database

### Exception Design Pattern
```python
class DocuSwarmError(Exception):
    def __init__(self, message: str, context: dict | None = None):
        super().__init__(message)
        self.message = message
        self.context = context or {}
```

### Use Cases by Exception Type
- **ConfigurationError**: Missing required env vars, invalid YAML config, schema validation failures
- **StorageError**: Database connection lost, file write permission denied, table creation failures
- **LLMError**: API key invalid, rate limit exceeded, malformed API response, timeout
- **NodeExecutionError**: Node timeout, invalid state transition, evaluation failure
- **ContextIsolationError**: Predecessor context missing when required, circular dependency detected
