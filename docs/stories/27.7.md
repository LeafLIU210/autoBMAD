## Dev Notes

### Architecture Context
- The `ContextValidator` is a facade that delegates to specific strategy classes
- Each strategy implements the `ValidationStrategy` ABC with a `validate()` method
- `ValidationRuleRegistry` allows per-node customization of validation rules
- Tests should mock external dependencies (LLM calls) appropriately

### Testing Approach
- Use pytest fixtures for reusable test data
- Mock LLM responses for `LLMContextValidationStrategy` tests
- Test both positive cases (valid data passes) and negative cases (invalid data caught)
- Verify error messages are clear and actionable

### File Locations
- **Test File**: `tests/unit/context/test_validator.py`
- **Source**: `autoBMAD/docuswarm/context/validator.py`
- **Related**: `autoBMAD/docuswarm/context/__init__.py` (exports)

### Dependencies
- Requires Story 27.1 (ContextValidator framework) to be completed
- Requires Story 27.2-27.5 (strategy implementations) for full test coverage
- Uses pytest, pytest-asyncio for async strategy tests

### Quality Standards

- Include docstrings for complex test scenarios
- Ensure tests run in isolation (no dependencies between tests)
