## Dev Notes
- The agent file uses kimi-agent-sdk's `agent_file` specification format
- Tool entries use the format `"module.path:ClassName"` for SDK to dynamically import
- The `extend: default` ensures base agent capabilities are inherited
- Evaluator agent should NOT have an agent file (or empty tools list) since it only evaluates
- Agent file path should be configurable via project configuration or environment variable
- SDK expects agent file to be in YAML format with specific schema (version, agent, tools keys)
- Consider adding validation for agent file format before passing to SDK
- The tools registered in agent file must be importable Python classes (CallableTool2 subclasses)

### Agent File Structure
```yaml
version: 1
agent:
  extend: default
  tools:
    - "docuswarm.tools.create_deliverable:CreateDeliverableTool"
    - "docuswarm.tools.update_context:UpdateContextTool"
```

### Implementation Notes
- KimiSessionManager.create_session() signature change: `async def create_session(self, mode: str, agent_file: str | None = None) -> KimiSession`
- Pass agent_file path to SDK session creation method
- SDK will automatically discover and instantiate tool classes from the YAML configuration
