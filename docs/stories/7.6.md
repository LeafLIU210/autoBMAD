## Dev Notes
- **Exception Hierarchy**: The kimi-agent-sdk provides typed exceptions that should map to DocuSwarm's existing exception hierarchy for consistency
- **Context Preservation**: Always use `from e` when re-raising exceptions to preserve the full stack trace
- **Partial Results**: MaxStepsReached should return partial messages (via MessageAggregator.flush()) rather than raising an error, allowing the application to decide how to handle incomplete responses
- **Graceful Degradation**: RunCancelled is not an error condition - the session was intentionally stopped, so log at info level and return gracefully
- **Logging Strategy**: Use structured logging with context (exception message, session_id, tool_name where applicable) for all caught exceptions
- **Type Safety**: Ensure type hints are updated to reflect that methods may return partial results or empty lists instead of always raising exceptions

### Exception Mapping Reference
```python
# Mapping in single_prompt() and session prompt loops
except ChatProviderError as e:
    raise LLMError(f"Kimi API error: {e}") from e
except RunCancelled:
    logger.info("execution_cancelled", session_id=session_id)
    return []  # Graceful return
except MaxStepsReached:
    logger.warning("max_steps_reached", max_steps=max_steps)
    return aggregator.flush()  # Return partial messages
except ConfigError as e:
    raise ConfigurationError(f"SDK config error: {e}") from e
except InvalidToolError as e:
    logger.error("invalid_tool_error", tool_name=e.tool_name, message=str(e))
```
