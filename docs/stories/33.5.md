## Dev Notes
- **Backward Compatibility is Critical**: The existing `deliverable` field must remain unchanged in type and structure. New functionality is additive only via computed properties.
- **Multi-Document Format Reference**: According to EPIC-33, multi-document deliverables use this structure:
  ```json
  {
    "deliverable": {
      "title": "Deliverables Set",
      "type": "multi-document",
      "documents": [
        {"index": 1, "type": "epic-list", "file_path": "...", "sha256": "...", "word_count": 1500},
        {"index": 2, "type": "story-prioritization", "file_path": "...", "sha256": "...", "word_count": 2300}
      ]
    }
  }
  ```
- **Single-Document Format**: Traditional format where `deliverable` is a single dict with `file_path`, `sha256`, `title`, etc.
- **Property Implementation Strategy**: Use `@property` decorators for computed fields to avoid data duplication and maintain single source of truth.
- **Type Safety**: Ensure type hints are accurate (e.g., `list[dict]`, `bool`, `int`) for IDE support and mypy validation.
- **Performance Considerations**: Properties are computed on access - document lists are expected to be small (< 10 items), so O(n) iteration is acceptable.
- **Edge Cases to Handle**:
  - `deliverable` is None
  - `deliverable.documents` is missing or empty list
  - `word_count` field missing from individual documents
  - Mixed documents where some have word_count and others don't
- **Orchestrator Integration**: The orchestrator in Story 33.6 will use these properties to collect and pass documents downstream. Ensure the interface aligns with their expectations.
