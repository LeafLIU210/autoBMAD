# Story 37.4: Update Context Builder to Use Cached Summary

## Status

**Status**: Ready for Done

**Last Updated**: 2026-04-07 09:31:54

## Story
**As a** pipeline execution system,
**I want** the context builder to use cached `docs_context_summary` from PipelineState instead of rebuilding it from disk for every node,
**So that** pipeline execution is significantly faster (~2.5 seconds saved per pipeline) and docs_context is consistently shared across all 5 nodes.

## Acceptance Criteria
- [x] `context_builder.build()` reads `docs_context` from `original_context["docs_context_summary"]` when the cached summary is present
- [x] Falls back to `_resolve_reference_docs()` method when cache is missing, with appropriate warning log
- [x] `_resolve_reference_docs()` method is PRESERVED (not deleted or modified) for backward compatibility and fallback scenarios
- [x] Original caching behavior remains unchanged for cases where `docs_context_summary` is not provided
- [x] Info log emitted when cache hit occurs: `using_cached_docs_summary` with `node_id` and `count`
- [x] Warning log emitted when fallback occurs: `missing_cached_docs_summary_using_fallback` with `node_id` and `count`
- [x] `NodeExecutionContext` is correctly constructed with the `docs_context` from cache or fallback

## Dev Notes
- **File Location**: `autoBMAD/docuswarm/node_execution/context_builder.py`
- **Method to Modify**: `build()` method of `ContextBuilder` class
- **Key Implementation Detail**: Check `if "docs_context_summary" in original_context:` before the existing `elif repo_root is not None:` check
- **Logging**: Use the existing logger instance; log messages should be structured (key=value format) for consistency with existing codebase
- **Backward Compatibility**: The fallback ensures pipelines without the new field continue to work exactly as before
- **Performance Impact**: This change reduces docs_context construction from 5 times per pipeline to effectively 0 times (when cache is available)
- **Dependencies**: This story depends on Story 37.3 (PipelineAdapter) which injects the summary into `original_context`

### Code Change Summary
```python
docs_context: list[dict[str, Any]] = []

# NEW: Prioritize cached summary (injected by PipelineAdapter)
if "docs_context_summary" in original_context:
    docs_context = original_context["docs_context_summary"]
    logger.info(
        "using_cached_docs_summary",
        node_id=node_id,
        count=len(docs_context),
    )
elif repo_root is not None:
    # Fallback: rare case when no cache available
    docs_context = self._resolve_reference_docs(original_context, node_id, repo_root)
    logger.warning(
        "missing_cached_docs_summary_using_fallback",
        node_id=node_id,
        count=len(docs_context),
    )
```
