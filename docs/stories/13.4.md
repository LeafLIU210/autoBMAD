# Story 13.4: 结构化重试逻辑

## Status
**Status**: Ready for Done

**Last Updated**: 2026-03-02 01:36:29

## Story
**As a** 开发者,
**I want** 实现结构化重试逻辑,
**So that** 当 LLM 返回的 JSON 解析失败时可以自动重试，提高验证成功率并记录详细的失败信息。

## Acceptance Criteria
- [x] 最多重试 `max_retries` 次（默认2次，总共尝试 max_retries+1 次）
- [x] 记录每次尝试的错误信息，包括异常类型和错误消息
- [x] 重试成功时返回结果并正确标记 `attempts` 字段为实际尝试次数
- [x] 所有重试都失败时调用 `_handle_validation_failure` 进入失败处理流程
- [x] 每次重试前记录日志，包含当前尝试次数和错误信息
- [x] 支持在重试循环中捕获 JSON 解析错误、LLM 调用错误等各类异常

## Tasks / Subtasks
- [x] Task 1: 在 `ContextValidator.validate` 方法中实现 for 循环重试逻辑
  - 使用 `range(self._max_retries + 1)` 实现最多 max_retries+1 次尝试
  - 每次循环捕获 Exception 异常
- [x] Task 2: 记录每次尝试的错误信息
  - 创建 `last_error` 和 `last_raw_response` 变量保存错误状态
  - 使用 logger 记录每次失败的详细信息
- [x] Task 3: 跟踪并记录尝试次数
  - 在返回成功结果时设置 `result.attempts = attempt + 1`
  - 将尝试次数传递到 failure handler
- [x] Task 4: 实现重试失败时的失败处理
  - 当所有重试耗尽后，调用 `_handle_validation_failure`
  - 传递 last_error、last_raw_response 和 attempts 参数

## Dev Notes
- 重试循环应使用 `for attempt in range(self._max_retries + 1)` 格式，确保最后一次attempt后不再continue
- 在 except 块中，需要判断 `attempt < self._max_retries` 来决定是否继续重试
- `_parse_validation_response` 可能抛出 json.JSONDecodeError 或其他异常，需要统一捕获
- 每次重试间隔可以考虑添加短暂延迟（可选，当前实现无延迟）
- `last_raw_response` 应保存原始响应内容，便于失败时调试
- 日志级别使用 INFO 记录重试，ERROR 记录最终失败
