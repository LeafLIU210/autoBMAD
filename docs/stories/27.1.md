### Key Technical Details

#### Data Models (from research/refactor-2026-03-26/01-context-validator-extraction.md)

**ValidationIssue**:
```python
@dataclass
class ValidationIssue:
    field: str          # 问题字段路径，如 "deliverable.file_path"
    message: str        # 问题描述
    severity: str       # "error" | "warning" | "info"
    code: str           # 问题代码，如 "MISSING_REQUIRED_FIELD"
```

**ValidationResult**:
```python
@dataclass
class ValidationResult:
    valid: bool
    issues: list[ValidationIssue] = field(default_factory=list)
    warnings: list[ValidationIssue] = field(default_factory=list)
    metadata: dict[str, Any] = field(default_factory=dict)

    @property
    def has_errors(self) -> bool: ...
    def add_error(self, field, message, code): ...
    def add_warning(self, field, message, code): ...
```

**ValidationStrategy ABC**:
```python
class ValidationStrategy(ABC):
    @abstractmethod
    def validate(self, data: Any, config: dict[str, Any] | None = None) -> ValidationResult: ...
    @property
    def strategy_name(self) -> str: ...
```

#### ContextValidator 主类方法签名
```python
class ContextValidator:
    def __init__(self, session_manager: Any | None = None) -> None: ...
    def load_node_rules(self, node_id: str, config: dict[str, Any]) -> None: ...
    def validate_execution_context(self, context: dict[str, Any], node_id: str | None = None) -> ValidationResult: ...
    def validate_isolation(self, data: dict[str, Any]) -> ValidationResult: ...
    def validate_independent_output(self, output: dict[str, Any], node_id: str = "") -> ValidationResult: ...
    def validate_evaluator_output(self, output: dict[str, Any], node_id: str = "") -> ValidationResult: ...
    async def validate_context_with_llm(self, subject_context: dict[str, Any], node_id: str = "") -> ValidationResult: ...
```

### Implementation Notes
1. **Strategy placeholders**: The five strategy classes (`NodeExecutionContextStrategy`, `PrivateFieldIsolationStrategy`, `LLMContextValidationStrategy`, `IndependentOutputValidationStrategy`, `EvaluatorOutputValidationStrategy`) will be implemented in subsequent stories (27.2-27.5). For this story, they can be minimal stubs or None.

2. **Import compatibility**: Do NOT delete or modify `node_execution/validator.py` yet - it will be handled in Story 27.3.

3. **Fail-open principle**: When implementing the actual strategies later, LLM validation should fail open (default to valid) if LLM is unavailable.

4. **Session manager**: The `session_manager` parameter is required for `LLMContextValidationStrategy` but optional for the facade. If not provided, `validate_context_with_llm` should raise RuntimeError.
