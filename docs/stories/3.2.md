## Dev Notes
- **Configuration Path Resolution**: Node configurations live in `nodes/{node_id}/` relative to the project root. Use `pathlib.Path` with proper path resolution to ensure cross-platform compatibility.
- **Validation Strategy**: Perform validation immediately after loading to fail fast. Use descriptive error messages that include the missing field name.
- **Type Safety**: Use dataclasses or TypedDict for NodeConfig to provide IDE autocomplete and type checking. This helps developers understand the configuration structure.
- **Persona Loading**: The persona.json contains the Independent Agent's system prompt and behavior instructions. This is critical for node behavior consistency.
- **Evaluator Loading**: The evaluator.yaml contains criteria for determining if a deliverable meets quality standards. It should include scoring rules and rejection conditions.
- **Sequence Validation**: The sequence number determines node execution order in the pipeline. Ensure sequence numbers are unique and sequential (1-5).
- **Dependencies**: The `predecessors` list defines which nodes' deliverables are chained as context. Analyst has no predecessors; each subsequent node adds more predecessors.
- **Error Handling**: Wrap file I/O in try/except to provide clear error messages. Distinguish between missing files (FileNotFoundError) and invalid YAML/JSON (parse errors).
