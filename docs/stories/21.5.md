## Dev Notes

### Technical Considerations

1. **New YAML Format Template**:
   The new format uses `task` block instead of inline description, questions, and dependencies. Each node must include:
   - `task.name`: Identifier for the BMM task
   - `task.description`: Detailed task description
   - `task.role_supplement`: Additional role context for the agent
   - `deliverable.template_title`: Template title with placeholders
   - `deliverable.output_filename`: Output filename pattern

2. **Backward Compatibility**:
   - Old fields (description, questions, dependencies) should be removed
   - NodeLoader should handle missing task block gracefully (set to None)
   - Existing tests that don't use deprecated fields should still pass

3. **BMM Role Alignment**:
   - Analyst: create-product-brief
   - PM: create-prd
   - UX: create-ui-spec
   - Architect: create-technical-spec
   - PO: create-product-backlog

4. **Placeholder Patterns**:
   - `template_title`: Use "{project_name}" placeholder for later formatting
   - `output_filename`: Use "{project_name}" in filename pattern

5. **File Locations**:
   - `nodes/analyst/node.yaml`
   - `nodes/pm/node.yaml`
   - `nodes/ux/node.yaml`
   - `nodes/architect/node.yaml`
   - `nodes/po/node.yaml`

6. **Required Sections**:
   Each deliverable type should have appropriate required_sections:
   - Product Brief: executive_summary, core_vision, problem_statement
   - PRD: overview, functional_requirements, non_functional_requirements
   - UI Spec: layout, components, interactions, accessibility
   - Technical Spec: architecture, api_design, data_model, security
   - Product Backlog: user_stories, priorities, acceptance_criteria

### Ralph's Principles to Follow
- **DRY**: Don't repeat role_supplement patterns across nodes unnecessarily
- **KISS**: Keep YAML structure simple and consistent
- **YAGNI**: Only add fields that are currently needed
- **Occam's Razor**: Prefer the simplest configuration that meets requirements
