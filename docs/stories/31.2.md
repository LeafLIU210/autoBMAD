## Story
**As a** DocuSwarm developer,
**I want** the SessionManager to enable SDK native Skills auto-discovery and allow the "Skill" tool to be invoked,
**So that** Claude can leverage the 50+ BMAD skills in `.claude/skills/` through the Agent SDK's native mechanism instead of manual system prompt injection.

## Dev Notes
- **SDK Configuration**: The `setting_sources=["project"]` tells the Claude Agent SDK to scan the project directory for `.claude/skills/` and auto-discover available skills. This replaces the current manual injection approach.
- **Tool Ordering**: Adding `"Skill"` as the first entry in `allowed_tools` is intentional - it prioritizes skill invocation and aligns with the new hybrid approach where skills are primary tools.
- **Backward Compatibility**: The `_get_builtin_tools()` extraction should not change the behavior of existing code - it's a refactoring to improve code organization and prepare for future tool permission enhancements from Story 31.1.
- **File Location**: Target file is `autoBMAD/docuswarm/llm/session_manager.py` which contains the `SessionManager` class responsible for creating `ClaudeAgentOptions`.
- **Integration Point**: This story works in conjunction with Story 31.1 (NodeToolPermissions extension) and Story 31.5 (IndependentAgent integration) - the `allowed_tools` will eventually incorporate per-node skill whitelists.
- **No Breaking Changes**: Existing functionality including MCP tools, checkpointing, and other Agent SDK features must continue to work exactly as before.
