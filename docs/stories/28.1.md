## Story
**As a** developer,
**I want** `NodeExecutionContext` to only contain runtime-dynamic fields,
**So that** static configuration is not redundantly passed through the execution protocol, eliminating the triple DRY violation and achieving single source of truth from `persona.json` + `node.yaml`.

## Dev Notes

### 精简后的 NodeExecutionContext 结构

```python
class NodeExecutionContext(TypedDict):
    # === 身份标识（运行时生成）===
    pipeline_id: str
    node_id: str
    node_name: str
    node_order: int
    # === 运行时上下文数据 ===
    original_context: dict[str, Any]
    chained_deliverables: list[dict[str, Any]]
    shared_context: dict[str, Any]
    # === 迭代状态 ===
    iteration_feedback: dict[str, Any] | None
    # === 扩展上下文 ===
    docs_context: list[dict[str, Any]]
```

### 重要保留项
- **`DeliverableArtifact`**: 运行时产物结构，需保留
- **`IndependentAgentInput` / `EvaluatorAgentInput`**: 隔离层输入结构，需保留
- **`IndependentOutput` / `EvaluatorOutput`**: 类型别名，需保留

### 依赖关系
- **前置依赖**: EPIC-25（清理 `persona_context` 和 `evaluator_criteria`）、EPIC-26（NodeConfig v2 提供 `task` 字段）
- **并行开发**: Story 28.2, 28.3, 28.4（消费端迁移可并行，但需协调变更顺序）

### 风险与注意事项
1. **破坏性变更**: 此修改将移除多个字段，影响所有消费端（已在 Story 28.2-28.4 中规划修复）
2. **类型兼容性**: 确保 `IndependentAgentInput` 等保留类型的字段完整性
3. **测试依赖**: 部分单元测试可能依赖已删除字段，需在对应消费端 Story 中同步更新
