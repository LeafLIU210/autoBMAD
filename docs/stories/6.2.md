## Dev Notes
- The kimi-cli `--wire` mode runs as a subprocess that communicates via stdin/stdout using the Wire protocol
- The subprocess requires the `KIMI_API_KEY` environment variable to be accessible
- On Windows, ensure the kimi-cli executable is in PATH after installation
- If using a virtual environment, verify subprocess can find the kimi-cli binary
- Some corporate proxies may interfere with kimi-cli communication - document any workarounds
- The Wire protocol uses JSON messages over stdio - no network ports need to be exposed
- Consider timeout handling for subprocess operations (default 60s recommended)
- SDK's Session class handles Wire protocol internally, but this task verifies the底层 infrastructure
