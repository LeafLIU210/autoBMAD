## Dev Notes

### Technical Context
The shared context mechanism is a cross-node shared dictionary in `PipelineState` that allows nodes to communicate and persist data across the pipeline execution. The existing `update_context.py` tool provides set/append/remove operations with whitelist protection.

### Critical Bug Being Fixed
The primary issue is that `executor.py` doesn't refresh `shared_context` from the database after tool calls. When a node completes, `graph.py` returns the in-memory state which may not contain the tool's DB writes, causing the next node to receive stale shared_context.

### Data Flow for Testing
```
Node A executes → calls update_context tool → Tool writes to SQLite
                                    ↓
Node A completes → executor refreshes from DB → Returns updated state
                                    ↓
Node B receives → shared_context contains Node A's updates
```

### Key Components to Test
1. **StateManager** (`autoBMAD/docuswarm/storage/state_manager.py`) - Database persistence
2. **UpdateContextTool** (`autoBMAD/docuswarm/tools/update_context.py`) - Context updates
3. **Executor** (`autoBMAD/docuswarm/node_execution/executor.py`) - DB refresh logic at line 360
4. **NodeLoader** (`autoBMAD/nodes/loader.py`) - Permission parsing

### Test Data Structure
```python
# Sample shared_context structure
shared_context = {
    "facts": {"market_scope": "global"},
    "decisions": {"architecture": "microservices"},
    "open_questions": ["Q1", "Q2"],
    "doc_summaries": {"readme": "..."},
    "notes": "general notes",
    "_metadata": {
        "version": 1,
        "updated_at": "2026-04-07T10:30:00Z"
    }
}
```

### Whitelist Configuration
Global whitelist (hardcoded in update_context.py):
- `facts.*`
- `decisions.*`
- `open_questions`
- `doc_summaries.*`
- `notes`

Per-node whitelist (configured in node.yaml):
```yaml
tools:
  shared_context:
    enabled: true
    operations: ["set", "append", "remove"]
    allowed_keys:
      - "facts.*"
      - "custom.key"
```

### Mocking Strategy
- Use in-memory SQLite for StateManager tests
- Mock LLM calls in node execution to focus on shared_context behavior
- Use temporary directories for any file-based operations

### Concurrency Considerations
Current execution model is strictly sequential (no parallelism), so:
- No need for complex locking tests
- Focus on sequential consistency
- Verify no race conditions in single-threaded scenario

### Integration Tests (Primary Focus)
- [x] `test_shared_context_persists_across_nodes()` - **CRITICAL**: End-to-end node-to-node propagation
  ```python
  # Pseudocode
  pipeline = create_pipeline()
  node_a_execute(pipeline, update_context={"facts.test": "value_a"})
  result = node_b_execute(pipeline, read_context="facts.test")
  assert result == "value_a"
  ```
- [x] `test_whitelist_blocks_unauthorized_keys()` - Security enforcement
  ```python
  # Pseudocode
  pipeline = create_pipeline()
  result = update_context(pipeline, key="unauthorized.key", value="test")
  assert result.success == False
  assert "not in whitelist" in result.error_message
  ```
- [x] `test_version_increments_on_update()` - Metadata tracking
  ```python
  # Pseudocode
  pipeline = create_pipeline()
  v1 = get_context_version(pipeline)
  update_context(pipeline, key="facts.test", value="v1")
  v2 = get_context_version(pipeline)
  assert v2 == v1 + 1
  assert get_timestamp(pipeline) is not None
  ```
- [x] `test_context_refresh_from_db()` - Executor DB refresh verification
  ```python
  # Pseudocode
  pipeline = create_pipeline()
  # Simulate tool writing directly to DB
  state_manager.update_shared_context(pipeline.id, {"facts.test": "db_value"})
  # Execute node that should refresh from DB
  executor.refresh_context_from_db(pipeline)
  assert pipeline.shared_context["facts.test"] == "db_value"
  ```
- [x] `test_concurrent_writes_safe()` - Data integrity
  ```python
  # Pseudocode
  pipeline = create_pipeline()
  for i in range(10):
      update_context(pipeline, key="facts.counter", value=i)
  final_value = pipeline.shared_context["facts.counter"]
  assert final_value == 9  # Last write wins in sequential model
  ```
