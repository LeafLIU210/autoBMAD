# Story 36.5: Update PipelineAdapter to Propagate Summaries

## Status

**Status**: Ready for Done

**Last Updated**: 2026-04-07 10:38:25

## Story
**As a** pipeline node execution system,
**I want** to receive pre-computed document summaries from PipelineState through PipelineAdapter,
**So that** context builder can access cached summaries instead of re-reading and re-processing documents from disk.

## Acceptance Criteria
- [x] `docs_context_summary` from PipelineState is injected into `original_context` passed to context builder
- [x] Context file serialization includes summary data when summaries are available
- [x] When `docs_context_summary` is empty or missing, `original_context` falls back to `subject_context` without modification
- [x] `PipelineAdapter.convert_pipeline_to_node_state()` signature and return type remain unchanged
- [x] Implementation maintains backward compatibility with pipelines that don't have summary cache

## Tasks / Subtasks
- [x] Task 1: Modify `convert_pipeline_to_node_state()` to extract `docs_context_summary` from pipeline_state
- [x] Task 2: Implement conditional injection logic: merge docs_context_summary into original_context when present
- [x] Task 3: Ensure `serialize_context()` receives the enriched original_context with summary data
- [x] Task 4: Add debug logging for summary presence/absence to aid troubleshooting
- [x] Task 5: Write unit tests verifying summary propagation through the adapter

## Dev Notes
- **File Location**: `autoBMAD/docuswarm/node_execution/pipeline_adapter.py`
- **Key Method**: `PipelineAdapter.convert_pipeline_to_node_state(pipeline_state, node_id) -> NodeRunState`
- **Implementation Pattern**: Check for `docs_context_summary` key in pipeline_state; if present and non-empty, merge into original_context
- **Merge Strategy**: Use dict spread `{**subject_context, "docs_context_summary": docs_summary}` to inject the summary list
- **Backward Compatibility**: When `docs_context_summary` is missing or empty, pass `subject_context` unchanged to preserve existing behavior
- **Serialization Impact**: The `serialize_context()` function must handle the enriched context; verify it can serialize list[DocumentSummary] or list[dict] types
- **Performance Consideration**: This is a simple dict operation with negligible overhead; no async operations needed
- **Related Stories**: This story depends on Story 36.3 (HybridOrchestrator integration) which populates `docs_context_summary` in PipelineState
- **Downstream Consumer**: ContextBuilder (Story 36.4) checks for `docs_context_summary` in original_context to use cached data
