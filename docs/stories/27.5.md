## Dev Notes
- **策略模式实现**: `LLMContextValidationStrategy` 继承 `ValidationStrategy` ABC，实现 `validate` 抽象方法
- **异步处理**: 策略类的 `validate` 方法应为 `async def`，因为涉及 LLM API 调用
- **异常边界**: `ContextValidator.validate_context_with_llm()` 负责将 `ValidationResult` 转换为 `ContextValidationError`，保持调用方异常契约
- **依赖注入**: `HybridOrchestrator` 不再自行创建验证器，而是通过构造函数接收，便于测试时 Mock
- **行数验证**: 迁移后 `orchestrator.py` 中验证相关代码应缩减至 ≤ 5 行（仅保留调用语句）
- **常量迁移**: 原 `CONTEXT_VALIDATION_PROMPT` 从模块级常量移至策略类内部，避免命名空间污染
- **配置保留**: 如果 `orchestrator.py` 中有其他配置项依赖验证逻辑，确保同步迁移
