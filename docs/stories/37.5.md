# Story 37.5: Update graph.py to Pass Summary to NodeRunState

## Status

**Status**: Ready for Done

## Story
**As a** DocuSwarm pipeline developer,
**I want** the `docs_context_summary` to be extracted from the LangGraph pipeline state and passed through to the PipelineAdapter during node execution,
**So that** each node can receive the cached document summary without rebuilding it from disk, eliminating duplicate work and improving pipeline performance by ~2.5 seconds per run.

## Acceptance Criteria
- [x] `docs_context_summary` is correctly extracted from LangGraph `PipelineState` in the `_create_integrated_node_executor()` function
- [x] The extracted `docs_context_summary` is passed to `PipelineAdapter.convert_pipeline_to_node_state()` for inclusion in the node's `original_context`
- [x] The change does not break existing graph execution flow - all existing pipeline nodes continue to function correctly
- [x] When `docs_context_summary` is present in the pipeline state, it is propagated to all 5 pipeline nodes (analyst, pm, ux, architect, po)
- [x] When `docs_context_summary` is missing or empty, the pipeline gracefully handles it without errors

## Dev Notes
- **File Location**: `autoBMAD/docuswarm/pipeline/graph.py`
- **Key Function**: `_create_integrated_node_executor()` - This function creates the node executor that runs within the LangGraph state graph
- **Integration Point**: The `PipelineAdapter.convert_pipeline_to_node_state()` method is responsible for converting the LangGraph `PipelineState` into a `NodeRunState` that individual nodes consume
- **State Access Pattern**: Use `pipeline_state.get("docs_context_summary", [])` to safely extract the field with a default empty list for backward compatibility
- **LangGraph Context**: This change operates within the LangGraph StateGraph framework - ensure the state extraction happens within the node executor function that receives the state dict
- **Related Stories**: 
  - Story 37.1: Adds `docs_context_summary` field to `PipelineState` TypedDict
  - Story 37.3: Updates `PipelineAdapter` to inject summary into `original_context`
  - This story (37.5) is the bridge that connects the two - extracting from state and passing to adapter
- **Performance Impact**: This change enables the 5x reduction in `docs_context` builds (from 5 per pipeline to 1 per pipeline)
- **Error Handling**: The extraction should be defensive - if the field is missing, pass an empty list to maintain backward compatibility with old checkpoints
