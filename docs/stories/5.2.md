# Story 5.2: Iteration Control Implementation

## Status
**Status**: Ready for Done
**Last Updated**: 2026-02-20 22:40:46

## Story
**As a** developer,
**I want to** control iteration flow within node execution,
**So that** nodes iterate until the deliverable is approved or the maximum iteration count is reached, preventing both premature acceptance and runaway loops.

## Acceptance Criteria
- [ ] AC-1: Track iteration count per node — each node maintains its own `current_iteration` counter starting at 0 and incrementing on every execution pass
- [ ] AC-2: Max 3 iterations enforced — once `current_iteration >= max_iterations` (default 3), no further iterations are permitted regardless of verdict
- [ ] AC-3: Feedback passed to next iteration — accumulated feedback from all prior iterations is available to the executing agent before each new pass
- [ ] AC-4: Iteration history preserved — every iteration records its `alignment_score`, `verdict`, `issues`, `deliverable_summary`, and generated `feedback` in an ordered list
- [ ] AC-5: `should_iterate` returns `True` only when verdict is `NEEDS_REVISION` and max iterations have not been reached
- [ ] AC-6: `start_iteration` creates a new `NodeIterationState` on first call for a node and reuses the existing state on subsequent calls
- [ ] AC-7: Accumulated feedback is formatted as a human-readable multi-section string suitable for injection into agent prompts

## Dependencies

## Dev Notes

### Technical Considerations
- The `evaluation` dict schema is: `{"alignment_score": float, "verdict": str, "issues_found": List[str], "suggestions": List[str]}`. Use `.get()` for optional keys (`issues_found`, `suggestions`) with empty-list defaults.
- `structlog` is the project-standard logging library. Bind `component="IterationController"` for consistent log filtering.
- `IterationController` is instantiated once per pipeline run and tracks state for all nodes in that run via the `self.states` dict keyed by `node_id`.
- Dataclasses are preferred over Pydantic for internal domain objects in this layer (consistent with Epic 3 patterns).
- `max_iterations` defaults to 3 but must be injectable for testing and future configuration (Story 5.1 `QualityConfig` may override per-node).

### Architecture Notes
- This module lives at `docuswarm/nodes/iteration.py` per the Epic key-files table.
- `IterationController` is a pure domain object with no async I/O — all methods are synchronous.
- Story 5.8 (DualAgentNode integration) will own the async execution loop that calls these methods.

### Principles
- **KISS**: Simple dict-based state tracking; no database persistence needed at this layer.
- **DRY**: Feedback formatting is centralised in `_generate_feedback`.
- **YAGNI**: No persistence, no serialisation, no event emission — those can be added in later stories if needed.
