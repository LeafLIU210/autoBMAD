## Dev Notes
- Integration tests require real Kimi API credentials (set via environment variables)
- Use `pytest.mark.integration` to separate integration tests from unit tests
- Session cleanup is critical - use fixtures with proper teardown
- Cancellation tests need careful timing - use asyncio.sleep() to allow prompt to start before cancelling
- Pipeline resume tests require LangGraph checkpoint SQLite database
- Mock the actual LLM responses if rate limiting is a concern during CI
- Consider adding `@pytest.mark.skipif` for CI environments without API access
- Test data should be minimal - use simple prompts that complete quickly

### Technical Considerations
- The test file should import from `docuswarm.llm.session_manager`, `docuswarm.llm.approval`, and `docuswarm.pipeline.orchestrator`
- Use `pytest-asyncio` for async test support
- Session IDs for tests should follow the naming convention: `docuswarm-test-{uuid}`
- Approval handler tests should verify both approve and reject paths
