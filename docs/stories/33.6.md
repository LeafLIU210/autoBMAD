## Story
**As a** DocuSwarm pipeline operator,
**I want** the orchestrator to handle multiple deliverables per node execution,
**So that** nodes like Architect and PO can produce multiple related documents in a single workflow step while maintaining proper document chaining to downstream nodes.

- [x] Integration test verifies architect node can produce and pass 2+ documents to the next node
- [x] Document metadata (sha256, file_path, word_count) is preserved for all documents in multi-doc set

## Dev Notes
- **File Location**: `autoBMAD/docuswarm/pipeline/orchestrator.py`
- **Multi-Document Format** (from Epic):
  ```json
  {
    "deliverable": {
      "title": "Deliverables Set",
      "type": "multi-document",
      "documents": [
        {"index": 1, "type": "system-architecture", "file_path": "...", "sha256": "..."},
        {"index": 2, "type": "api-design", "file_path": "...", "sha256": "..."}
      ]
    }
  }
  ```
- **Backward Compatibility**: The existing `deliverable` field in `NodeResult` must remain unchanged for single-document flows. Multi-document support is additive only.
- **Pipeline State Considerations**: State storage may need versioning to handle both formats. Consider storing `deliverables: list[dict]` alongside the original `deliverable: dict` field.
- **Chaining Logic**: When building `chained_deliverables` for the next node, multi-document results should be flattened into the list so downstream nodes see all documents uniformly.
- **Integration with Story 33.5**: Coordinate with `NodeResult` changes (if implemented in parallel) to ensure `is_multi_document`, `all_documents`, and `total_word_count` properties are utilized.
- **Performance**: Document count should be limited (max 5 per Epic spec) to prevent state bloat.
