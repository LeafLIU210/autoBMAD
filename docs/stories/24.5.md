## Dev Notes

### Technical Considerations
- **Layer 1 (work_dir)**: The create_deliverable tool saves directly to the agent's working directory during execution. This is the "first line of defense" for deliverable persistence.
- **Layer 2 (output/{pipeline_id}/)**: FileStorage.save_deliverable saves to the canonical output location with proper naming. This is the "source of truth" for deliverables.
- **Atomic Write**: Use temp file with rename pattern: write to {filename}.tmp, then rename to {filename}. This ensures either the old file exists or the new file exists, never a partial file.
- **Filename Mapping**: Refer to FILENAME_MAP constant for node_type to filename conversion. Support aliases (pm/prd, architect/architecture, po/epics).
