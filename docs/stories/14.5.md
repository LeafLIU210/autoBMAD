## Story
**As a** developer working on the ToolResultExtractor component,
**I want to** generate standardized file paths from document titles using a slugify function,
**So that** all created documents have consistent, URL-safe filenames that follow project conventions.

## Acceptance Criteria
- [ ] **Lowercase Conversion**: All uppercase letters in titles are converted to lowercase (e.g., "My Document" → "my document")
- [ ] **Space to Hyphen**: All spaces are replaced with hyphens (e.g., "my document" → "my-document")
- [ ] **Special Character Removal**: All non-alphanumeric characters except hyphens are removed (e.g., "my@document#test" → "mydocumenttest")
- [ ] **Multiple Hyphen Consolidation**: Consecutive hyphens are merged into single hyphen (e.g., "my---document" → "my-document")
- [ ] **Leading/Trailing Hyphen Removal**: Hyphens at the start or end of the filename are stripped (e.g., "-my-document-" → "my-document")
- [ ] **MD Extension**: All generated filenames end with ".md" extension
- [ ] **Empty Title Fallback**: Empty or whitespace-only titles default to "document.md"
- [ ] **Unicode Handling**: Unicode characters are handled gracefully (kept as-is or removed based on regex pattern)

## Dev Notes
- The `_slugify` method should be a `@staticmethod` since it doesn't require instance state
- Use regex pattern `r"[^a-z0-9\-]"` to match characters that are NOT lowercase letters, digits, or hyphens
- Use regex pattern `r"-+"` to match multiple consecutive hyphens
- Consider edge cases: Unicode characters (currently removed), very long titles, titles with only special characters
- The method should be idempotent - calling it multiple times with the same input produces the same output
- This slugify implementation follows common URL slug conventions used in web development
