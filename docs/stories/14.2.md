## Dev Notes
- The Kimi SDK uses a content list structure where each part has a `type` attribute
- Tool calls are represented as `tool_use` type parts within the content list
- The `input` field contains the actual tool parameters (title, content, metadata, etc.)
- Must handle the case where content is None, not a list, or empty
- The extraction should be case-sensitive for the type field ("tool_use")
- This method will be called by `extract_from_messages` alongside other format extractors
- Ensure consistent return type (list[DeliverableMetadata]) with other extraction methods

## Technical Considerations
- Kimi SDK format: `message.content = [{"type": "tool_use", "name": "create_deliverable", "input": {...}}]`
- Must use getattr with defaults to safely access attributes
- The SUPPORTED_TOOLS set defines which tools to process: {"create_deliverable", "create_document_set"}
- The _parse_tool_params method handles the actual conversion of tool params to metadata objects
