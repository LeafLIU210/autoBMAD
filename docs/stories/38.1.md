# Story 38.1: EvaluatorAgent — SDK `output_format` 集成

## Status
**Status**: Ready for Done

**Last Updated**: 2026-04-07 18:47:26  

## Story
**As a** DocuSwarm pipeline operator,  
**I want** EvaluatorAgent to use SDK's native `output_format` mechanism for structured output validation,  
**So that** JSON parsing failures no longer cause pipeline termination and the system has reliable error recovery.

## Acceptance Criteria
- [ ] `session_manager.py::single_prompt()` accepts optional `output_format: dict | None = None` parameter
- [ ] `_create_options()` injects `output_format` into `ClaudeAgentOptions` when the parameter is provided
- [ ] `evaluator_config/schemas.py` defines `EVALUATOR_OUTPUT_SCHEMA` constant with JSON Schema format
- [ ] `evaluator.py::_call_llm_with_prompt()` passes `output_format=EVALUATOR_OUTPUT_SCHEMA` to `single_prompt()`
- [ ] `evaluator.py::_parse_response()` prioritizes reading from `ResultMessage.structured_output` over manual JSON extraction
- [ ] `error_max_structured_output_retries` subtype messages are handled by raising `EvaluationError` with proper logging
- [ ] Original `extract_json()` path is retained as fallback when `structured_output` is not available
- [ ] All 5 EvaluatorAgent output fields are constrained by the schema:
  - `criterion_scores` (dynamic key: float 0.0-1.0)
  - `alignment_score` (float 0.0-1.0)
  - `verdict` (enum: APPROVED/NEEDS_REVISION/BLOCKED)
  - `issues_found` (array of strings)
  - `suggestions` (array of strings)

## Dev Notes
- **Schema Definition Location**: Add `EVALUATOR_OUTPUT_SCHEMA` to `autoBMAD/docuswarm/agents/evaluator_config/schemas.py` alongside existing types like `CriteriaWeights` and `EvaluationCriteria`
- **Backward Compatibility**: The `extract_json()` fallback ensures existing behavior continues to work during migration; this path can be deprecated in future releases
- **Error Handling**: When `error_max_structured_output_retries` is received, raise `EvaluationError("SDK structured output retries exhausted")` - this maintains consistent error handling with existing `EvaluationError` usage
- **Value Validation**: Even with SDK schema validation, the `_parse_response()` method should still perform clamping and alignment_score recalculation as defensive programming
- **Response Format**: When `structured_output` is available, return format should be `[{"type": "structured", "data": <schema_validated_data>}]` to maintain consistency with existing response handling
- **SDK Documentation**: Reference `autoBMAD/agentdocs/14_structured_outputs.md` for `output_format` usage patterns and `autoBMAD/agentdocs/19_custom_tools.md` for JSON Schema patterns
