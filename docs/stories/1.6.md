# Story 1.6: File Storage for Deliverables

## Status
**Status**: Ready for Development

**Last Updated**: 2026-02-20 14:07:55

## Story
**As a** developer,
**I want to** save deliverables to markdown files,
**So that** outputs are accessible and version-controllable.

## Acceptance Criteria
- [ ] Create node run output directory structure (`output/{node}/{run-id}/`)
- [ ] Save deliverable content as `deliverable.md` with proper UTF-8 encoding
- [ ] Generate `evaluation.json` with evaluation metadata (scores, timestamps, iteration)
- [ ] Generate `questions.json` with node questions and answers if applicable
- [ ] Support file export command via CLI to export deliverables to custom location
- [ ] Overwrite existing files if re-running the same node with same run-id
- [ ] Create parent directories automatically if they don't exist
- [ ] Return file paths for all generated files for reference

## Dev Notes
- Use `pathlib.Path` for all file operations - cross-platform compatibility
- Ensure atomic writes using temporary files + rename for crash safety
- Add docstrings to all public methods following the project's coding standards
- Consider async file I/O using `aiofiles` for non-blocking writes
- Follow Ralph's principles: DRY (use shared utilities), KISS (simple file operations), YAGNI (no cloud storage for v1)
- FileStorage should integrate with StateManager to retrieve node run data for export
- Metadata JSON should include: run_id, node_id, created_at, iteration, evaluation_scores (if available)
- Consider adding file locking mechanism for concurrent access scenarios
- Use `ensure_directory_exist()` pattern with `parents=True, exist_ok=True`
