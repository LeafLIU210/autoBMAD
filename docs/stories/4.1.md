## Story
**As a** developer,
**I want** to have a context manager that controls access to context data,
**So that** agents receive only appropriate context based on their role (Independent Agent gets full access, Evaluator gets restricted access).

## Dev Notes

### Architecture Considerations
- The ContextManager is the first layer of defense in the three-layer isolation system (per Epic 4 architecture)
- This class operates at Layer 2: Runtime Access Control
- The filter at Layer 3 (ContextFilter) will handle actual removal of private fields; this class validates that private data doesn't leak

### Dependencies
- Requires `structlog` for logging (already in project dependencies)
- No external dependencies beyond typing
- Part of the `docuswarm/context` module package

### Integration Points
- Will be used by `DualAgentNode` to build context for both agents
- Works in conjunction with `ContextFilter` (Story 4.2) and `MemoryManager` (Story 4.3)
- Audit logging will be handled by `IsolationAuditLogger` (Story 4.4) - this class logs to audit via the node, not directly

### Edge Cases
- Handle None values for optional parameters (iteration_feedback)
- Handle empty dictionaries for subject_context, chained_deliverables, etc.
- Validate nested dictionaries for private fields (deferred to ContextFilter for deep checking)

### Performance Considerations
- Context builders should be lightweight - just dictionary construction and validation
- No expensive operations (no I/O, no API calls)
- Deep copying should be avoided here (delegated to ContextFilter)
