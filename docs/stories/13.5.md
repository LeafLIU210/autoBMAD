## Story
**As a** developer,
**I want to** implement a configurable error handling strategy (fail-open/fail-close),
**So that** I can choose between strict or lenient validation modes based on the environment.

## Acceptance Criteria
- [x] When `fail_open=True`: return `valid=True` but mark `fallback_used=True` in ValidationResult
- [x] When `fail_open=False`: raise `ContextValidationError` with detailed error message
- [x] The reason/description includes failure details (attempt count, last error)
- [x] Log the strategy choice and fallback usage for observability
- [x] The `reason` field contains descriptive failure information

## Tasks / Subtasks

- [x] Task 2: Add conditional logic based on `self._fail_open` configuration

- [x] Task 5: Raise ContextValidationError when fail_open=False

## Dev Notes
- The `_handle_validation_failure` method should be called when all retry attempts are exhausted
- This method acts as the final fallback after JSON parsing failures and validation failures
- The `fail_open` parameter should be configurable via ContextValidator constructor
- Default behavior should be `fail_open=False` for production safety
- The `raw_response` field should capture the last LLM response for debugging
- Log levels: use ERROR for failure, WARNING when fallback is used
