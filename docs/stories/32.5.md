## Dev Notes

### Node Configuration Changes
**File**: `nodes/architect/node.yaml`

The `task.skill_ref` field is a new addition to the node configuration schema. This field tells the `IndependentAgent` which BMAD skill to invoke when executing this node. The value `bmad-create-architecture` should correspond to an installed skill in the `.claude/skills/` directory.

The `role_supplement` provides additional context to the agent's system prompt, emphasizing the need to:
1. Balance technical excellence with business constraints
2. Make implicit architectural knowledge explicit in documentation
3. Document all trade-off decisions thoroughly (options, rationale, risks, mitigation)

### Persona Configuration Changes
**File**: `nodes/architect/persona.json`

The persona is being enhanced with:
- **Name**: "Winston" - Gives the agent a distinct identity aligned with BMAD methodology
- **Role**: Clarified as "System Architect & Technical Design Leader"
- **Principles**: Added architectural best practices:
  - "Simplicity over complexity" - Encourages straightforward solutions
  - "Embrace boring technology for stability" - Favors proven technologies over trendy ones

### Dependencies
- This story depends on EPIC-31 (Skills Introduction) being complete, as the `skill_ref` field requires the SkillInjector infrastructure
- The `bmad-create-architecture` skill must exist in `.claude/skills/`

### Backward Compatibility
- The `skill_ref` field should be optional in the schema to maintain backward compatibility
- Nodes without `skill_ref` should continue to work without errors
