**Status**: Ready for Review

## Story
**As a** system architect,
**I want** to configure the analyst, pm, and ux nodes to enforce a single-document constraint,
**So that** these nodes can only create exactly one deliverable per execution, ensuring document creation consistency and preventing accidental multi-document submissions.

## Dev Notes
- **Prerequisite**: Story 33.1 (NodeDeliverableConfig Extension) must be completed first. The `NodeLoader` at `autoBMAD/nodes/loader.py` needs to understand the `max_deliverables` field before these configuration changes take effect.
- **File Locations**: All target files are under `autoBMAD/nodes/` directory, NOT the deprecated `nodes/` directory. The `NodeLoader` only reads from `autoBMAD/nodes/`.
- **Configuration Structure**: The expected YAML structure is:
  ```yaml
  deliverable:
    max_deliverables: 1
    required_sections:
      - section1
      - section2
  ```
- **Backward Compatibility**: Ensure existing fields like `required_sections` are preserved when adding the new `max_deliverables` field.
- **Validation**: After modifications, verify that:
  1. YAML files are syntactically valid
  2. NodeLoader can parse the new field
  3. System prompts correctly reflect the single-document constraint
- **Related Stories**: This story works in conjunction with Story 33.2 (Validator enhancement) and Story 33.8 (System prompt guidance) to enforce the single-document constraint end-to-end.
