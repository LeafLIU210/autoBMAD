# Story 22.5: 重构 _format_system_prompt()

## Status
**Status**: Ready for Done

**Last Updated**: 2026-03-02 22:26:20

## Story
**As a** developer,
**I want** to refactor the system prompt building method,
**So that** it assembles all sections in the correct order.

## Acceptance Criteria

### AC1: Complete Section Assembly
- [x] **Given** all section formatting methods are implemented (_format_persona_section, _format_task_section, _format_deliverable_section)
- [x] **When** I call _format_system_prompt()
- [x] **Then** it returns a complete prompt string containing all four sections joined by double newlines

### AC2: Correct Section Ordering
- [x] **Given** the complete system prompt output
- [x] **When** I examine its structure
- [x] **Then** sections appear in this exact order:
  1. Persona Section (formatted from self.persona)
  2. Task Assignment (formatted from self.task_config)
  3. Deliverable Requirements (formatted from self.deliverable_config)
  4. Execution Instructions (from _format_execution_instructions)

### AC3: Placeholder Preservation
- [x] **Given** a deliverable config with template_title containing placeholders (e.g., "{project_name}")
- [x] **When** _format_system_prompt() is called
- [x] **Then** all placeholders in template_title are preserved exactly as-is for runtime substitution

### AC4: Execution Instructions Format
- [x] **Given** the _format_execution_instructions() static method
- [x] **When** it's called
- [x] **Then** it returns a formatted string containing:
  - "## Execution Instructions" header
  - Instruction to use 'create_deliverable' tool
  - Instruction to include all required sections
  - Instruction to generate at least 3 clarifying questions
  - Instruction to document reasoning in 'private_reasoning'

### AC5: Empty Config Handling
- [x] **Given** optional parameters (task_config, deliverable_config) may be None
- [x] **When** _format_system_prompt() is called with None values
- [x] **Then** the corresponding section formatters handle None gracefully (existing methods)

## Dev Notes

- **Method Location**: The `_format_system_prompt()` method belongs in the `IndependentAgent` class alongside the other `_format_*` section methods
- **Dependencies**: This story depends on Stories 22.1-22.4 being complete (all section formatting methods implemented)
- **Placeholder Handling**: The method should NOT resolve or substitute placeholders - that happens at runtime when the deliverable is actually created
- **Section Joining**: Use `"\n\n"` (double newline) to create clear visual separation between sections in the final prompt
- **Backward Compatibility**: Existing behavior should not change - this is a refactor, not a behavior change
