## Story
**As a** system architect,
**I want** to add a `submit_execution_report` MCP tool with strict JSON Schema validation,
**So that** IndependentAgent's execution report fields are fully constrained, eliminating the risk of malformed JSON causing pipeline failures and increasing constraint coverage from 57% to 100%.

### Schema 设计要点
- `deliverable` 对象必须包含 `title`, `file_path`, `sha256`；`content_summary` 可选
- `questions` 数组可选，但每项必须包含 `question`, `priority`, `context`
- `priority` 枚举值必须与现有代码中的硬编码字符串完全一致
- `action` 当前仅支持 `"create_deliverable"`，为未来扩展预留其他操作类型

### 工具调用顺序
系统提示应明确要求 LLM 按以下顺序调用工具：
1. 首先调用 `create_deliverable` 创建交付物
2. 获取返回值中的 `file_path` 和 `sha256`
3. 立即调用 `submit_execution_report` 提交执行报告

### 向后兼容性
- 保留原有 `_parse_response()` 解析逻辑作为兜底路径
- 新工具结果优先，旧路径在新路径不可用时继续工作
- 避免破坏现有节点执行流程

### 与 Story 38.4 的依赖关系
本 Story 完成后，Story 38.4 将更新系统提示以明确工具调用顺序要求。
