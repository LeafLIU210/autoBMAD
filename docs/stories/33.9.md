## Dev Notes

### Test Architecture
The test file should follow the existing test structure in the `tests/` directory. Use pytest with fixtures for setup. Mock the dependencies rather than testing actual LLM calls.

### Key Test Patterns
```python
# Single-document constraint violation test pattern
def test_analyst_rejects_second_deliverable():
    # Setup: Create first deliverable
    # Action: Attempt to create second deliverable
    # Assert: Validator returns failure with clear message

# Multi-document success test pattern
def test_architect_creates_multiple_deliverables():
    # Setup: Configure max_deliverables=4 for architect
    # Action: Create 4 deliverables with document_index 1-4
    # Assert: All succeed, NodeResult shows is_multi_document=True
```

### Mock Strategy
- Mock `NodeLoader` to return test configurations
- Mock file system operations for `file_path` validation
- Mock LLM responses to simulate tool calls
- Use `tmp_path` fixture for temporary file operations

### Validation Error Messages
Tests should verify validator provides clear error messages:
- "Document count (2) exceeds max_deliverables limit (1) for node 'analyst'"

- Existing callers using only `title`, `content`, `file_path`, `sha256` should work unchanged
- Existing `NodeResult.deliverable` access patterns should continue to work
- Existing pipeline state handling should not require changes for single-doc cases
