## Story

**I want** the config completeness checker to validate all v2 schema fields including task configuration, correct evaluator field names, and persona communication style,
**So that** the reported "100% completeness" metric reflects genuine configuration validity rather than producing false-positives that mask missing required fields.

## Dev Notes
- The `node_config_completeness_checker.py` is located in the `tools/` directory and is a standalone diagnostic utility
- Current implementation may use a simple field presence check; v2 schema requires nested field validation (e.g., `task.name` not just `task` section exists)
- The `threshold` vs `thresholds` check is case-sensitive and must match the exact field name used in the NodeEvaluatorConfig data class
- Consider adding a schema version detection mechanism to allow the checker to adapt its validation rules based on `schema_version` field in node.yaml
- The checker should output a per-node breakdown showing: node name, overall completeness percentage, and a list of missing/invalid fields
- False-positive elimination is critical: the current tool reports 100% completeness even when `task.name` is missing because it only checks for `task` section existence
- For backward compatibility during the transition period, the checker could report both v1 and v2 completeness scores with a deprecation warning for v1-only configs
- The 5 nodes to validate are: analyst, pm, ux, architect, po - each located at `autoBMAD/nodes/{node_name}/`
