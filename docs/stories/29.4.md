# Story 29.4: SessionManager MCP 集成

## Status
**Status**: Ready for Done

**Last Updated**: 2026-03-28 05:09:42

## Story
**As a** session manager,
**I want** to register node-specific MCP servers during agent initialization,
**So that** file and search tools are available during agent execution with proper permission boundaries.

- [x] `allowed_tools` 列表包含 MCP 工具的完整命名（`mcp__docuswarm-files-{node_id}__read_document`、`mcp__docuswarm-files-{node_id}__list_documents`、`mcp__docuswarm-search-{node_id}__grep_search`、`mcp__docuswarm-search-{node_id}__glob_search`）

- [x] 支持向后兼容：当 `node_id` 为 None 时，SessionManager 行为与之前一致（不注册 MCP 服务器）

## Dev Notes
- **MCP Server 命名规范**: 文件服务器命名为 `docuswarm-files-{node_id}`，搜索服务器命名为 `docuswarm-search-{node_id}`，确保不同节点的工具命名空间隔离
- **工具权限链**: `node.yaml` → `NodeToolPermissions` → `SessionManager` → `ClaudeAgentOptions.allowed_tools`，任何环节缺失都应阻止工具注册
- **参数传递路径**: `IndependentAgent._call_llm_with_prompts` → `SessionManager` → `ClaudeAgentOptions`，需在调用处从 `self.node_config.tool_permissions` 提取 `allowed_dirs`
- **SDK 兼容性**: `ClaudeAgentOptions.mcp_servers` 接受 `List[McpServer]` 类型，需从 `autoBMAD.docuswarm.tools` 模块导入对应 server 创建函数
- **向后兼容策略**: 保持 `node_id` 默认为 `None`，确保现有测试和直接实例化场景不受影响
- **性能考虑**: MCP 服务器应在每次 `_create_options` 调用时重新创建，确保权限配置最新；或考虑缓存但监听配置变更
