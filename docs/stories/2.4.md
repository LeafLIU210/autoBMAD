## Story
**As a** developer
**I want to** parse and validate LLM responses from both Independent and Evaluator agents
**So that** agent outputs are structured correctly and can be reliably consumed by downstream components

## Acceptance Criteria
- [x] JSON extraction from LLM responses handles direct JSON, JSON in code blocks (```json), and JSON embedded in markdown
- [x] Independent Agent output validates against IndependentOutput schema (deliverable, questions, private_reasoning)
- [x] Evaluator Agent output validates against EvaluatorOutput schema (criterion_scores, alignment_score, verdict, issues_found, suggestions)
- [x] Malformed responses trigger clear, actionable error messages with response context for debugging
- [x] Partial valid responses are handled gracefully with appropriate warnings
- [x] Response parsing handles edge cases: empty responses, very large responses, responses with special characters

## Dev Notes
- Use Python's `typing.TypedDict` for schema definitions as specified in Epic
- Consider using `pydantic` or `dataclasses` for runtime validation if TypedDict is insufficient
- JSON extraction should attempt multiple strategies in order: direct parse, code block extraction, regex pattern matching
- Alignment score must be clamped to 0.0-1.0 range during validation
- Verdict must be one of: "APPROVED", "NEEDS_REVISION", "BLOCKED"
- Questions list items must have required fields: priority (blocking|clarifying|optional), question, context
- Deliverable must have required fields: title, content; optional: metadata
- Consider adding a `ResponseParseError` custom exception for clear error handling
- Include response preview (first 200 chars) in error messages for debugging
