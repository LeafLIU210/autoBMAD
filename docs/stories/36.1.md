# Story 36.1: Create SummaryAgent Class

## Status

**Status**: Ready for Done

**Last Updated**: 2026-04-07 10:40:04

## Story

**As a** pipeline orchestrator,
**I want** a SummaryAgent that pre-processes referenced documents to generate structured LLM summaries,
**so that** document context can be cached once and reused by all 5 pipeline nodes, eliminating ~2.5 seconds of redundant processing per pipeline run.

## Acceptance Criteria

- [ ] `SummaryAgent` class exists in `autoBMAD/docuswarm/agents/summary.py` with `summarize_context()` async method
- [ ] `DocumentSummary` dataclass defined with all required fields: `filename`, `path`, `size_bytes`, `summary`, `key_points`, `structure`, `truncated`, `llm_tokens_used`
- [ ] LLM generates valid structured JSON output for test documents matching schema `{summary, key_points, structure: {sections, concepts}}`
- [ ] Batch processing implemented with max 3 concurrent LLM calls using asyncio semaphore
- [ ] Critical files (containing "requirement" in name) processed sequentially before normal files
- [ ] Graceful error handling: returns `None` for failed files, logs warning, continues processing other files
- [ ] Timeout handling: 30 seconds per document with max 2 retries
- [ ] Temperature set to 0.3 for deterministic output, max_tokens limited to 1000 per document
- [ ] Unit tests in `tests/test_summary_agent.py` with >80% coverage

## Dev Notes

### Architecture Context

**Integration Point**: This Story 36.1 creates the SummaryAgent that generates document summaries. It depends on EPIC-37 which provides the persistence layer (`docs_context_summary` field in PipelineState). The SummaryAgent runs once at pipeline start (in `HybridOrchestrator.start_pipeline()`) and stores results in the initial pipeline state.

**Data Flow**:
```
HybridOrchestrator.start_pipeline()
    ↓
SummaryAgent.summarize_context(subject_context)
    ↓ reads original_context to find referenced filenames
    ↓ reads each file completely (no truncation)
    ↓ calls LLM to generate structured JSON summary per file
    ↓ returns list[DocumentSummary]
    ↓
initial_state["docs_context_summary"] = docs_summary   [cached by EPIC-37]
    ↓
graph.ainvoke(initial_state)
    ↓
Each node: context_builder reads from cache (Story 36.4, EPIC-37)
```

**JSON Schema for LLM Output**:
```json
{
  "summary": "2-5 sentence core summary of the document",
  "key_points": ["3-7 key points extracted from the document"],
  "structure": {
    "sections": ["list of main sections"],
    "concepts": ["key concepts mentioned"]
  }
}
```

**Concurrency Pattern**:
```python
semaphore = asyncio.Semaphore(3)  # Max 3 concurrent

async def process_with_limit(file):
    async with semaphore:
        return await process_file(file)

# For critical files (sequential):
for file in critical_files:
    result = await process_file(file)

# For normal files (concurrent):
normal_results = await asyncio.gather(
    *[process_with_limit(f) for f in normal_files],
    return_exceptions=True
)
```

### Performance Considerations

- **Target**: < 30 seconds total for summary generation
- **Max concurrent**: 3 LLM calls simultaneously
- **File size limit**: Skip files > 500KB (log warning)
- **No truncation**: Unlike current `_resolve_reference_docs()`, read full files for LLM processing
- **Sequential for critical**: Files with "requirement" in name processed first sequentially to ensure quality

### Error Handling Strategy

| Scenario | Behavior |
|----------|----------|
| LLM timeout (>30s) | Return None, log warning, continue |
| LLM returns invalid JSON | Retry up to 2 times, then return None |
| File not found | Log warning, skip file |
| File unreadable (binary/corrupt) | Return "unable to read" summary |
| File > 500KB | Log warning, skip file |
| All retries exhausted | Return None, log error |
