## Dev Notes
- WAL (Write-Ahead Logging) mode allows concurrent reads during writes
- `synchronous=NORMAL` provides good balance between safety and performance
- The `is_alive` lambda is required by LangChain's BaseCheckpointSaver interface
- This method is called internally by `get_or_create` when no cached checkpointer exists
- Consider logging the checkpointer creation for debugging purposes

### Implementation Details
```python
async def _create_checkpointer(self, pipeline_id: str) -> AsyncSqliteSaver:
    import aiosqlite

    # Create async connection for the checkpointer
    db_file = self._db_path.replace(".pystr", f"_{pipeline_id}.pystr")

    # Create async connection
    conn = await aiosqlite.connect(db_file)

    # Execute WAL mode PRAGMA
    await conn.execute("PRAGMA journal_mode=WAL")

    # Execute synchronous PRAGMA for optimal performance
    await conn.execute("PRAGMA synchronous=NORMAL")

    # Add is_alive method required by BaseCheckpointSaver interface
    conn.is_alive = lambda: True

    self._logger.info(
        "checkpointer_created_with_wal",
        pipeline_id=pipeline_id,
        db_file=db_file,
    )

    return AsyncSqliteSaver(conn=conn)
```

### Technical Considerations
- WAL mode creates separate `-wal` and `-shm` files alongside the main database
- Ensure proper cleanup of these files when closing connections
- The checkpointer should be cached after creation for reuse
