## Story
**As a** developer,
**I want to** process Markdown code blocks in LLM responses,
**So that** the JSON validation results can be correctly parsed regardless of formatting variations.

## Acceptance Criteria

- [x] Plain JSON without any Markdown formatting continues to work correctly
- [x] Whitespace is properly trimmed before JSON parsing

## Dev Notes
- The parsing logic should handle the following input formats:
  - Plain JSON: `{"valid": true, "reason": "OK"}`
  - JSON with json language tag: ````json\n{"valid": true}\n``` `
  - JSON with generic code block: ` ``` \n{"valid": true}\n``` `
  - JSON with mixed/inconsistent markers
- The method should strip content before attempting `json.loads()` to prevent parsing errors
- Consider using regex for more robust handling of edge cases
- Follow the KISS principle - keep the implementation simple and readable
- Ensure error messages clearly indicate when Markdown cleanup was attempted but parsing still failed
