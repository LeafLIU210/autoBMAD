# Story 33.7: Update Architect and PO node.yaml for Multi-Document

## Status

**Status**: Ready for Done

**Last Updated**: 2026-04-07 13:04:44

## Story
**As a** system architect and product owner,
**I want** the architect and PO node configurations to explicitly support multiple deliverables with defined document types,
**So that** the pipeline can correctly validate, collect, and process multiple documents from these nodes while guiding the LLM to create the appropriate number of documents.

## Acceptance Criteria
- [x] `autoBMAD/nodes/architect/node.yaml` has `deliverable.max_deliverables: 4` with valid `document_types` list
- [x] `autoBMAD/nodes/po/node.yaml` has `deliverable.max_deliverables: 5` with valid `document_types` list
- [x] All `document_types` values are validated against the allowed schema in `NodeDeliverableConfig`
- [x] System prompt generated by `contract_builder.py` includes document count guidance specific to architect (up to 4) and PO (up to 5) nodes
- [x] YAML files pass schema validation and `NodeLoader` can parse them without errors
- [x] Existing single-document nodes (analyst, pm, ux) remain unaffected by these changes

## Dev Notes
- **Dependency**: This story depends on **Story 33.1** (extend `NodeDeliverableConfig` in `autoBMAD/nodes/loader.py` to support `max_deliverables` and `document_types` fields). Do not start until 33.1 is complete.
- **Dependency**: This story depends on **Story 33.8** (system prompt guidance in `contract_builder.py`). Coordinate with the developer of 33.8 to ensure the prompt reads the new config values correctly.
- **Path Correction**: All changes must be made in `autoBMAD/nodes/` directory. The old `nodes/architect/` and `nodes/po/` directories are deprecated and ignored by `NodeLoader`.
- **Architectural Order**: Per EPIC-33, the correct extension order is: `loader.py` (config model) → `create_deliverable.py` (tool params) → `validator.py` (validation rules) → `node.yaml` (this story) → `contracts.py` (NodeResult) → `orchestrator.py` (collection logic).
- **Relevant Source Tree**:
  - `autoBMAD/nodes/loader.py` — `NodeDeliverableConfig` dataclass (must already have `max_deliverables: int` and `document_types: list[str]` fields from Story 33.1)
  - `autoBMAD/nodes/architect/node.yaml` — target file for architect multi-doc config
  - `autoBMAD/nodes/po/node.yaml` — target file for PO multi-doc config
  - `autoBMAD/docuswarm/prompts/contract_builder.py` — system prompt builder that consumes these values (Story 33.8)
  - `autoBMAD/docuswarm/context/validator.py` — reads `max_deliverables` to enforce constraints (Story 33.2)
