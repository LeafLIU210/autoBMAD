## Dev Notes
- **Type Hierarchy Overview**: The SDK provides a layered type system with Message (high-level), WireMessage (protocol-level), and ContentPart (content container) as core types
- **ContentPart Variants**:
  - `TextContentPart`: Contains `.text` field with string content
  - `ImageContentPart`: Contains `.image` field with image data/URL
  - `AudioContentPart`: Contains `.audio` field with audio data/URL
- **ChatResponse to Message Mapping**:
  - `.content` → `.content[0].text` (ContentPart)
  - `.usage.total_tokens` → Wire-level metadata (not directly exposed)
  - `.model` → Config-level (passed to Session.create)
  - `.finish_reason` → Wire message type (completion, tool_calls, etc.)
- **Exception Hierarchy Mapping**:
  - HTTP 429 → ChatProviderError (APIStatusError)
  - HTTP timeout → APITimeoutError
  - HTTP 5xx → ChatProviderError (APIStatusError)
  - Connection error → APIConnectionError
  - Empty response → APIEmptyResponseError
  - Cancel → RunCancelled (new)
  - Step limit → MaxStepsReached (new)
  - Config error → ConfigError (new)
  - Tool error → InvalidToolError (new)
- **Documentation Output**: Create a type-mapping document in `docs/research/sdk-type-mapping.md` for Phase 1 development reference
