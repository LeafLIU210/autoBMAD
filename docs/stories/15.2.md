## Acceptance Criteria
- [x] `@docs/path/to/file.md` resolves to `{project_root}/docs/path/to/file.md`
- [x] Supports multiple file extensions (md, txt, yaml, json)
- [x] When file does not exist, marks `exists=False` with appropriate error message
- [x] Content is correctly read from resolved file path
- [x] PATH_PATTERN regex correctly matches `@docs/` references with valid file extensions
- [x] Case-insensitive extension handling works correctly

## Tasks / Subtasks
- [x] Task 1: Implement `ContextResolver.__init__` to accept `project_root` parameter
  - Set `self.project_root` from parameter or default to `Path.cwd()`
  - Set `self.docs_root` as `self.project_root / "docs"`
- [x] Task 2: Define `PATH_PATTERN` regex in ContextResolver class
  - Pattern: `r"@([\w./\-\u4e00-\u9fff]+\.(?:md|txt|yaml|json))"`
  - Enable UNICODE support for international characters
- [x] Task 3: Implement `_resolve_single_reference` method
  - Accept `ref_path` and `context_file_path` parameters
  - Check if `ref_path.startswith("docs/")`
  - Resolve path relative to `project_root`
- [x] Task 4: Handle file reading and existence check
  - Use `Path.exists()` to verify file existence
  - Read file content using `Path.read_text(encoding='utf-8')`
  - Return `ReferencedDocument` with `exists=False` if file not found

## Dev Notes
- The `@docs/` prefix indicates paths relative to the project root's `docs` folder
- This is the first path format being implemented; other formats (@./, @/) will be handled in subsequent stories
- Ensure proper encoding handling (UTF-8) for international character support
- The `ReferencedDocument` dataclass will be defined in Story 15.1
- Consider logging for debugging path resolution issues
- Path resolution should use `pathlib.Path` for cross-platform compatibility
