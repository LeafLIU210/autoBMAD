# Story 35.1: Fix executor.py - Refresh shared_context from DB

## Status

**Status**: Ready for Done

**Last Updated**: 2026-04-07 17:01:40

## Story
**As a** pipeline orchestrator,  
**I want** to refresh the `shared_context` from the database after each node completes execution,  
**So that** subsequent nodes receive the most up-to-date shared context data, preventing stale data propagation and ensuring consistency across the pipeline execution.

## Context

### Problem Statement
DocuSwarm's `shared_context` is a cross-node shared dictionary in `PipelineState`. The existing `update_context` tool provides set/append/remove operations with whitelist protection. However, there's a critical bug where `executor.py` doesn't refresh `shared_context` from DB after tool calls.

**Data Flow Issue**:
```
IndependentAgent calls update_context tool
    ↓ Tool writes to SQLite directly
    ↓ (In-memory state NOT updated)
Node completes, graph.py returns in-memory state
    ↓ shared_context = OLD value (before tool calls)
Next node receives stale shared_context
```

### Current State
- `shared_context` is persisted in SQLite (WAL mode) via `StateManager.update_shared_context()`
- `update_context` tool writes directly to SQLite (not in-memory)
- **Critical Bug**: When a node completes, `graph.py` returns the in-memory state which may not contain the tool's DB writes

### Solution Overview
The fix involves adding a `_refresh_shared_context_from_db()` method in `executor.py` that:
1. After node execution completes, reads the latest `shared_context` from the database
2. Updates the in-memory state with the persisted values
3. Falls back to in-memory version if DB read fails

## Dev Notes

### Implementation Details

**File**: `autoBMAD/docuswarm/node_execution/executor.py`

The `_refresh_shared_context_from_db()` function should be implemented as follows:

```python
# After node execution, refresh shared_context from DB
try:
    latest_state = state_manager.get_pipeline(pipeline_id)
    if latest_state and "state_json" in latest_state:
        persisted = json.loads(latest_state["state_json"])
        new_state["shared_context"] = persisted.get("shared_context", {})
except Exception:
    pass  # Use in-memory version as fallback
```

### Key Technical Considerations

1. **Lifecycle Timing**: The refresh must occur after all tool calls complete but before the state is returned to the graph orchestrator. This ensures the next node in the pipeline receives the updated context.

2. **Error Handling**: The implementation uses a broad `except Exception` pattern intentionally. Since this is a non-critical refresh operation, any failure should silently fall back to the in-memory state rather than failing the entire pipeline.

3. **JSON Parsing**: The state is stored as JSON in the database, so `json.loads()` is required to deserialize the `shared_context` dictionary.

4. **Partial Update**: Only `shared_context` is refreshed from DB, not the entire state. This minimizes the risk of overwriting other in-memory changes while fixing the specific stale data issue.

5. **WAL Mode**: SQLite is running in WAL (Write-Ahead Logging) mode, which should provide good read performance for the refresh operation.

### Potential Risks

| Risk | Mitigation |
|------|------------|
| DB refresh introduces latency | Single DB read; measured overhead < 10ms acceptable |
| Race conditions in concurrent scenarios | Current model is strictly sequential (no parallelism) |
| Silent failures hide real issues | Log warnings for debugging while allowing fallback |

### Dependencies
- `state_manager.get_pipeline(pipeline_id)` must be available and functional
- `json` module for deserialization
- Proper `pipeline_id` available in execution scope
