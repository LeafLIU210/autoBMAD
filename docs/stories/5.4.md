## Acceptance Criteria
- [x] Questions are categorized by priority (BLOCKING, CLARIFYING, OPTIONAL)
- [x] BLOCKING questions prevent node progression until answered
- [x] User can answer questions via CLI commands
- [x] Answers are incorporated into the node run context for subsequent iterations
- [x] Questions are stored persistently and retrievable by run_id and node_id
- [x] Question context is preserved and displayed when answering

## Dev Notes
- Question IDs should follow format: `{node_id}_{run_id[:8]}_{index}` for uniqueness
- StateManager integration required for persisting answers into node_run_answers table
- Question context should include relevant excerpts from the deliverable or PRD that prompted the question
- The QuestionHandler should maintain in-memory cache of questions keyed by run_id
- Blocking questions must be checked before each iteration proceeds
- Consider adding question expiration or max questions per node to prevent accumulation
- CLI should display questions grouped by priority with blocking questions highlighted in red
