- On cancellation, the pipeline state should capture any partial outputs already generated before the cancellation was requested
- Resource cleanup must include: closing the SDK session, releasing any locks, and updating the LangGraph checkpoint
- The cancellation should propagate to any child nodes that are currently executing
- Consider adding a cancellation_reason parameter to track why cancellation was triggered (user_request, timeout, error)

### Cancellation Flow
```
External cancel request
  → PipelineOrchestrator.cancel_current_node()
    → SessionManager.get_active(session_id)
      → session.cancel()  # SDK native cancellation
        → asyncio.Event.set()
          → KimiCLI.run() detects cancel_event
            → Raises RunCancelled exception
              → Agent catches RunCancelled
                → Returns partial output
                  → Pipeline state updated to CANCELLED
```
