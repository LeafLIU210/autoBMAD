## Status
**Status**: Ready for Development

## Story
**As a** user,
**I want to** interact with DocuSwarm via command line,
**So that** I can start, monitor, and manage node runs efficiently.

## Acceptance Criteria
- [ ] `docuswarm start --context <file>` initiates pipeline execution with the provided context file
- [ ] `docuswarm status <pipeline_id>` shows detailed progress of the specified pipeline
- [ ] `docuswarm resume <pipeline_id>` resumes an interrupted pipeline from its last checkpoint
- [ ] `docuswarm export <pipeline_id> <output_dir>` exports pipeline deliverables to the specified output directory in markdown format
- [ ] `docuswarm list-pipelines` lists all pipelines with their status, subject, and current node
- [ ] `docuswarm list-pipelines --status <status>` lists pipelines filtered by status (pending, running, completed, failed, paused)
- [ ] `docuswarm questions <pipeline_id>` displays pending questions for a pipeline with question IDs
- [ ] `docuswarm answer <question-id> <answer>` submits an answer to a specific question and triggers re-evaluation
- [ ] Rich output with colors, progress bars, and formatted tables for all commands
- [ ] All commands provide helpful error messages when invalid arguments are provided

## Dev Notes
- Use Click's `click.echo()` with Rich's `Console()` for formatted output
- All commands should return exit code 0 on success, non-zero on failure
- Context file path should be validated for existence before passing to node execution
- Node validation should check against known node types: analyst, pm, ux, architect, po
- The `--no-chain` flag on start command should skip context chaining (don't inject predecessor deliverables)
- Export command should create output directory if it doesn't exist
- Use async/await patterns since StateManager operations are async
- Handle missing database gracefully - display helpful message to run `docuswarm init` first
- Store run history in reverse chronological order (newest first)
- Question IDs should be unique across all runs (consider format: {run_id}:{question_index})

## Known Issues (2026-02-23 Discovery)

### Issue 1: `start` Command Only Creates Metadata (P0)

**Problem**: CLI `start` command only calls `StateManager.create_pipeline()`, does NOT trigger `HybridOrchestrator.start_pipeline()`.

**Impact**: 
- Pipeline record created but LangGraph not executed
- `current_node` remains NULL
- No actual node execution occurs

**Required Fix**: Integrate `HybridOrchestrator.start_pipeline()` into CLI start command.

**Reference**: [DocuSwarm-CLI-Research-Report.md](../../autoBMAD/docuswarm/docs/DocuSwarm-CLI-Research-Report.md)

### Issue 2: `resume` Command Writes "unknown" to current_node (P1)

**Problem**: When `current_node` is NULL, resume command fills it with literal string "unknown".

```python
# Current problematic code
current_node: str = str(cast(str, pipeline.get("current_node")) or "unknown")
```

**Impact**: Database stores invalid node name "unknown".

**Required Fix**: 
- Call `HybridOrchestrator.resume_pipeline()` instead of direct status update
- Add `--node` option for restart from specific node
- Add `--force` option for running pipelines

### Issue 3: `status` Command Missing Node Status Table (P1)

**Problem**: Only displays `current_node`, not status of all 5 nodes.

**Required Fix**: Add node status table showing completed/running/pending for each node.

**Expected Output**:
