## Dev Notes

### Global Whitelist (Current Hardcoded Values)
The following keys are always allowed globally:
- `facts.*` - Any key under facts namespace
- `decisions.*` - Any key under decisions namespace
- `open_questions` - Specific key for tracking questions
- `doc_summaries.*` - Any key under doc_summaries namespace
- `notes` - Specific key for general notes

### Whitelist Merge Strategy
- **Approach**: Union of global whitelist + node-specific allowed_keys
- **Wildcard Support**: Both global and node-specific lists support `*` wildcards
- **Precedence**: Node-specific keys extend (not replace) global whitelist
- **Example**: If global has `facts.*` and node specifies `custom_key`, both are valid

### Error Message Format
```python
{
    "success": False,
    "error": "Key 'unauthorized.key' is not in the allowed whitelist",
    "key": "unauthorized.key",
    "operation": "set",
    "allowed_patterns": ["facts.*", "decisions.*", "open_questions", "doc_summaries.*", "notes", "custom.node.key"]
}
```

### Logging Requirements
Use `logger.debug()` to log:
- Source of whitelist being used ("global_only", "node_extended", "node_custom")
- Number of effective patterns in the merged whitelist
- Node ID making the request
