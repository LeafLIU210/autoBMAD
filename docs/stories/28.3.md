# Story 28.3: isolation.py Consumer Migration

## Status

**Status**: Ready for Done

**Last Updated**: 2026-03-27 21:01:42

## Story
**As a** isolation layer developer,
**I want** to read task configuration directly from NodeLoader instead of NodeExecutionContext,
**so that** the isolation layer is no longer dependent on NodeExecutionContext carrying redundant task-related fields, completing the Task Contract Elimination epic.

## Acceptance Criteria

1. **AC1: build_independent_input Migration**
   `build_independent_input()` method must read `task_name`, `task_description`, `role_supplement`, and `deliverable_requirements` directly from `NodeLoader().load(node_id)` instead of from `execution_context`.

2. **AC2: build_evaluator_input Migration**
   `build_evaluator_input()` method must read `criteria` from `NodeLoader().load(node_id).evaluator` (continuing the work from EPIC-25 Story 25.3), and also migrate `task_name` and `task_description` to read from NodeLoader.

3. **AC3: No Dual-Read Mechanism**
   The implementation must NOT use any fallback mechanism (no `execution_context.get("task_name")` as fallback). All task-related data must come exclusively from NodeLoader.

4. **AC4: Test Updates**
   `tests/unit/context/test_isolation.py` must be updated to reflect the new data flow, and all tests must pass.

### Technical Considerations

1. **Lazy Import Pattern**: The file already uses lazy import for `NodeLoader` in `build_evaluator_input()` (line 191). Follow this pattern for `build_independent_input()` to avoid circular imports:
   ```python
   from autoBMAD.nodes.loader import NodeLoader
   node_config = NodeLoader.load(node_id)
   ```

2. **Deliverable Requirements Construction**: The `deliverable_requirements` field in `IndependentAgentInput` is a dict. Construct it from `node_config.deliverable`:
   ```python
   deliverable_requirements = {
       "required_sections": node_config.deliverable.required_sections,
       "template_title": node_config.deliverable.template_title,
       "output_filename": node_config.deliverable.output_filename,
       "format_hints": {"format": node_config.deliverable.format},
   }
   ```

3. **Error Handling**: If `node_id` is missing from `execution_context`, raise `ValueError` (same pattern as in `build_evaluator_input`).

4. **NodeConfig Access Path**: Based on `loader.py`:
   - `node_config.task.name`
   - `node_config.task.description`
   - `node_config.task.role_supplement`
   - `node_config.deliverable.required_sections`
   - `node_config.deliverable.template_title`
   - `node_config.deliverable.output_filename`
   - `node_config.deliverable.format`
   - `node_config.evaluator.criteria`
