## Story
**As a** DocuSwarm system operator,
**I want** a dedicated YAML configuration file for the Summary Agent,
**So that** the Summary Agent's behavior (temperature, max tokens, concurrency limits, timeouts) can be centrally configured and easily adjusted without code changes.

- [ ] Config file validates successfully against the expected schema (agent_id, name, type, performance settings are present and valid types)
- [ ] `SummaryAgent` class can read and load all config values correctly (temperature, max_tokens, max_concurrent_documents, batch_size, timeout_per_document_seconds, max_retries)

- [ ] Concurrency limit (max 3 simultaneous documents) is enforced - no more than 3 concurrent LLM calls are made at any time
- [ ] Caching configuration values (enable, ttl_hours, invalidate_on_doc_change) are accessible to the SummaryAgent for future cache implementation

## Dev Notes
- **File Location**: The config file should be placed at `autoBMAD/docuswarm/config/summary_agent.yaml`
- **Config Schema**: Follow the same structure as other agent configs in the system for consistency
- **Default Values**: The configuration includes sensible defaults (temperature=0.3 for deterministic output, max_tokens=1000, timeout=30s)
- **Concurrency Control**: Use `asyncio.Semaphore(max_concurrent_documents)` to enforce the limit of 3 simultaneous LLM calls
- **Timeout Handling**: Each document processing should be wrapped with `asyncio.wait_for()` using the configured timeout_per_document_seconds
- **Graceful Degradation**: If config file is missing or invalid, SummaryAgent should use sensible defaults and log a warning
- **Tools Configuration**: The allowed tools (ListDocuments, ReadDocument) should be validated against the actual available tools registry
- **Caching**: While caching is configured, the actual implementation may be deferred to a later story (36.6+), but the config structure should support it
