## Dev Notes
- The execute_with_iteration method replaces the standard execute method for quality-controlled nodes
- Feedback from previous iterations must be passed to _execute_single_iteration to inform the agent
- VerdictDeterminer should be instantiated per-execution or as a class with static methods
- EscalationError must be caught by the node execution orchestrator to handle blocked nodes
- Metrics should be recorded BEFORE returning the result to ensure completeness
- The iteration controller maintains state across the while loop - no need to reset between iterations
- Questions are collected after each iteration but before verdict determination to allow iteration-specific questions
- The loop exits when either: APPROVED, FORCE_APPROVED, BLOCKED (raises exception), or should_iterate returns False
