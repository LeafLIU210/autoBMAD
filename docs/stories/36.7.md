## Dev Notes

### Overview
This story focuses on creating comprehensive end-to-end tests for the Summary Agent and Context Builder refactoring (EPIC-36). The tests must validate that the Summary Agent correctly generates structured document summaries, that the Context Builder uses cached summaries efficiently, and that the entire pipeline integrates correctly with these new components.

### Related Files and Components

**New Files to Create**:
- `tests/test_summary_agent.py` - Unit and integration tests for SummaryAgent class
- `tests/test_context_builder_with_cache.py` - Tests for ContextBuilder cache integration
- `tests/test_orchestrator_with_summary.py` - End-to-end pipeline tests with summary integration

**Files Under Test**:
- `autoBMAD/docuswarm/agents/summary.py` - SummaryAgent class and DocumentSummary dataclass
- `autoBMAD/docuswarm/node_execution/context_builder.py` - ContextBuilder with cache support
- `autoBMAD/docuswarm/pipeline/orchestrator.py` - HybridOrchestrator with summary integration
- `autoBMAD/docuswarm/node_execution/pipeline_adapter.py` - PipelineAdapter for summary propagation

### Key Implementation Details

**SummaryAgent Testing**:
- DocumentSummary dataclass fields: `filename`, `path`, `size_bytes`, `summary`, `key_points`, `structure`, `truncated`, `llm_tokens_used`
- LLM prompt generates structured JSON: `{summary, key_points, structure: {sections, concepts}}`
- Temperature: 0.3 (deterministic output)
- Max tokens: 1000 per document
- Processing: Critical files (containing "requirement") → sequential; Normal files → concurrent batch (max 3)
- Timeout: 30 seconds per document, max 2 retries

**ContextBuilder Cache Integration**:
- Check `original_context.get("docs_context_summary")` before calling `_resolve_reference_docs()`
- Log `using_cached_docs_summary` on cache hit
- Log `missing_cached_docs_summary_using_fallback` on cache miss
- Preserve `_resolve_reference_docs()` method for backward compatibility

**Orchestrator Integration**:
- `start_pipeline()` calls `_summarize_referenced_documents()` with 120-second timeout
- On timeout/error: fallback to empty list (pipeline continues)
- `resume_pipeline()` checks checkpoint for `docs_context_summary` and regenerates if missing

### Performance Targets
| Metric | Target |
|--------|--------|
| Summary generation time | < 30 seconds per pipeline |
| Pipeline startup additional delay | < 5 seconds |
| Node execution time change | No increase (uses cache) |
| Summary accuracy | > 80% (manual review) |
| Referenced doc coverage | 100% (all mentioned files) |
| Document truncation rate | 0% (full documents processed) |

### Risk Mitigations to Test
1. **LLM timeout blocks pipeline**: Verify 120s timeout + fallback to empty list
2. **Binary/corrupt document failure**: Verify LLM returns "unable to read" summary
3. **Token explosion from many large docs**: Verify max 3 concurrent; skip files >500kb
4. **Cache consistency on doc change**: Test file modification monitoring (if implemented)
5. **Pipeline resume missing cache**: Verify fallback to re-summarize or continue without

### Testing

#### Unit Tests
- **Test file location**: `tests/test_summary_agent.py`, `tests/test_context_builder_with_cache.py`
- **Test standards**: Follow existing pytest patterns in `tests/`
- **Frameworks**: pytest, pytest-asyncio for async tests, unittest.mock for LLM mocking
- **Patterns**: Use fixtures for sample documents, mock LLM responses for deterministic behavior

#### Integration Tests
- **Test file location**: `tests/test_orchestrator_with_summary.py`
- **Scope**: Full pipeline execution with real (or mocked) components
- **Database**: Use test database or in-memory SQLite for checkpoint testing
- **Async testing**: Use `pytest.mark.asyncio` for async test functions

#### Performance Tests
- **Benchmark fixtures**: Create document sets of varying sizes (1, 5, 10, 20 docs)
- **Timing assertions**: Use `time.perf_counter()` for accurate measurements
- **Load testing**: Verify concurrent document processing respects max 3 limit
