## Story
**As a** node loader system,
**I want** validation rules from `node.yaml` automatically registered in `ValidationRuleRegistry`,
**So that** each node can have its own customized validation configuration without hardcoding rules.

## Acceptance Criteria
- [x] `NodeLoader.load_node` 在加载节点配置后，提取 `node_yaml.get("validation", {})` 并通过 `ContextValidator.load_node_rules(node_id, validation_rules)` 注册
- [x] `ValidationRuleRegistry` 支持按 `node_id` 存储和检索验证规则（如 `min_word_count`, `required_sections`, `max_output_size`）
- [x] 当 `ContextValidator.validate_independent_output(node_id, output)` 被调用时，自动使用对应 `node_id` 的注册规则；若该节点无注册规则，则回退到全局默认规则
- [x] 若 `node.yaml` 中无 `validation` 配置块，系统使用预设的全局默认值（`min_word_count=100`, `required_sections=["analysis"]`）
- [x] 规则变更支持热加载：重新加载 `node.yaml` 时，新规则覆盖旧规则，无需重启服务

## Tasks / Subtasks

  - 调用 `ContextValidator.get_instance().load_node_rules(node_id, validation_config)`

  - 实现 `get_rules(node_id: str) -> dict` 方法，返回合并后的规则（节点规则覆盖全局默认）
  - 实现 `has_rules(node_id: str) -> bool` 辅助方法

## Dev Notes
- **文件定位**: `NodeLoader` 通常位于 `autoBMAD/docuswarm/node/` 或 `pipeline/` 目录，需先确认实际路径
- **单例模式**: `ContextValidator` 应采用单例模式，确保 `NodeLoader` 和验证调用方使用同一实例
- **规则合并策略**: 节点级规则与全局默认规则采用**浅合并**（shallow merge），节点规则优先级更高
- **线程安全**: `ValidationRuleRegistry` 内部使用 `threading.Lock` 保护 `_rules` 字典，支持并发加载节点
- **规则 Schema**: 建议的 `node.yaml` validation 块结构：
  ```yaml
  validation:
    min_word_count: 150
    required_sections:
      - "analysis"
      - "recommendations"
    max_output_size: 10000
    custom_rules:
      - type: "regex_match"
        field: "verdict"
        pattern: "^(PASS|FAIL|NEEDS_IMPROVEMENT)$"
  ```
- **向后兼容**: 若现有节点无 `validation` 配置，必须保持行为不变（使用默认规则通过验证）
- **日志记录**: 规则加载和覆盖时记录 `INFO` 级别日志，便于调试配置问题
