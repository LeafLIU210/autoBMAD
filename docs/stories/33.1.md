# Story 33.1: Extend CreateDeliverableParams

## Status

**Status**: Ready for Done

**Last Updated**: 2026-04-07 13:05:54

## Story
**As a** DocuSwarm system architect,
**I want** to extend the `CreateDeliverableParams` class with multi-document support fields,
**So that** the system can handle nodes that create multiple documents (like Architect and PO) while maintaining backward compatibility with single-document nodes.

## Context
This story is part of EPIC-33: Document Creation Constraints and Multi-Document Support. Currently, `CreateDeliverableTool` is designed for single-document creation only. To support Architect nodes (2-4 documents) and PO nodes (3-5 documents), we need to add metadata fields that track document position, total count, and document type within a multi-document set.

This is the foundational story that must be completed before Stories 33.2 (Validator), 33.3 (node.yaml updates), and subsequent multi-document support stories.

## Acceptance Criteria
- [x] `CreateDeliverableParams` class has three new optional fields:
  - `document_index: int | None = None` - 1-based position of this document in the set
  - `document_total: int | None = None` - total number of documents in the set
  - `document_type: str | None = None` - type identifier for this document (e.g., "system-architecture", "api-design")
- [x] All new fields have default value `None` to ensure backward compatibility
- [x] Existing callers without these fields continue to work without modification
- [x] Unit tests verify that new fields are properly validated (e.g., `document_index` must be >= 1 when provided, `document_total` must be >= `document_index` when both provided)
- [x] Returned metadata from tool execution includes new fields when they are provided
- [x] Field documentation clearly explains the purpose and constraints of each field
