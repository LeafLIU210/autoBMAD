## Status

**Status**: Ready for Done

## Story
**As a** system operator or developer debugging DocuSwarm,
**I want** to see clear, structured logs of tool configurations at session startup,
**So that** I can quickly verify that agents have the correct tool access and diagnose permission issues without examining configuration files manually.

## Acceptance Criteria
- [ ] Startup logs show structured entry: `tools_configured: {mcp_servers: N, allowed_tools: [...]}`
- [ ] Log includes file permission directories (`allowed_read_dirs`, `search_dirs`)
- [ ] Logging uses structured format compatible with structlog (JSON or key-value pairs)
- [ ] Logs are emitted at `INFO` level during Session initialization
- [ ] Tool configuration is logged exactly once per session creation (not per-agent or per-request)
- [ ] If no tools are configured, log explicitly states `tools_configured: null` or empty state for clarity

### Expected Log Format (Example)
```json
{
  "event": "session_initialized",
  "timestamp": "2026-04-07T10:30:00Z",
  "session_id": "sess_abc123",
  "tools_configured": {
    "mcp_servers": 2,
    "allowed_tools": ["Read", "Glob"],
    "file_permissions": {
      "allowed_read_dirs": ["docs/"]
    },
    "search_permissions": {
      "search_dirs": ["docs/"]
    }
  }
}
```

### Key Implementation Points
1. **Injection Point**: Log should be emitted in `SessionManager.__init__()` or `create_session()` method after tool configuration is loaded
2. **structlog Usage**: Use `structlog.get_logger()` and bind context fields for structured output
3. **Security**: Sanitize any MCP server URLs to remove credentials (user:password@host patterns)
4. **Performance**: Logging happens once at startup, no runtime overhead per request

### Tool Configuration Path
Based on Epic context, tools config structure in node.yaml:
```yaml
tools:
  allowed_builtin_tools: ["Read", "Glob"]
  file_permissions:
    allowed_read_dirs: ["docs/"]
  search_permissions:
    search_dirs: ["docs/"]
  mcp_servers:  # If present
    - name: server1
      url: ...
```

- `autoBMAD/docuswarm/nodes/node_loader.py` - May contain ToolConfig parsing logic
- `autoBMAD/docuswarm/tools/tool_registry.py` - Tool registration, may have MCP server info

### Log Level Decision
Use `INFO` level - this is important operational information that operators should see in normal operations, not just during debugging.
