## Story
**As a** developer,
**I want** to resume interrupted sessions via session_id,
**So that** agents can continue from where they left off after interruption.

## Dev Notes
- **Resume Flow**: The `resume_or_create()` method should first attempt to resume an existing session using the SDK's `Session.resume()`. If the session is not found (returns None), it should log the event and create a fresh session with the same session_id.
- **Error Handling**: Resume failures should be handled gracefully - never raise exceptions that block pipeline execution. Always fall back to fresh session creation.
- **Session ID Consistency**: The session_id used for resume must match the original session_id exactly (format: `docuswarm-{pipeline_id}-{node_id}[-iter{n}]`).
- **State Management**: Session metadata should be stored in LangGraph PipelineState to enable recovery after pipeline restart.
- **Logging**: Use structured logging with session_id, event type, and outcome for observability.
