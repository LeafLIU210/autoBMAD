## Story

## Dev Notes

### Tool Naming Convention
Search MCP servers should follow the naming pattern: `mcp__docuswarm-search-{node_id}` to ensure uniqueness per node and avoid conflicts.

### Path Security Requirements
- All paths must be normalized using `os.path.abspath()` before permission checking
- Path must start with one of the allowed `search_dirs` prefixes
- Reject any paths containing `..` or attempting directory traversal
- Return clear error message: "Path '{path}' is outside allowed search directories"

### grep_search Implementation Details
- Use Python's `re` module for regex matching
- Read files line by line to handle large files efficiently
- Compile regex with `re.MULTILINE` flag for cross-platform line endings
- Limit results to prevent token overflow (default 20, max 50)
- Include context: file path, line number, and matched line content

### Error Handling Strategy
```python
# Regex compilation error handling
try:
    compiled_pattern = re.compile(pattern)
except re.error as e:
    return f"Invalid regex pattern: {e.msg} at position {e.pos}"
```

### Performance Considerations
- Skip binary files (check for null bytes in first 1KB)
- Limit file size per search (skip files > 10MB)
- Early termination when max_results reached
- Use `os.scandir()` for efficient directory traversal

### Result Format
```python
{
    "results": [
        {
            "file": "docs/research/api-design.md",
            "line": 42,
            "content": "The authentication endpoint accepts Bearer tokens..."
        }
    ],
    "total_matches": 45,
    "truncated": True  # If more results exist beyond limit
}
```
